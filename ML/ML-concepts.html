Module 1 — Introduction · source: ML_CS 1_26th July 2026.pdf

What is Machine Learning

The science of programming computers so they can learn from data — giving computers the ability to learn without being explicitly programmed. Engineering definition: a program learns from experience E with respect to task T and performance measure P, if its performance at T (measured by P) improves with E. A well-defined task is the tuple <P, T, E>.

ML_CS 1 · p16

Traditional Programming vs Machine Learning

Traditional: data + hand-written program → output. ML: data + desired output → the computer produces the program (model). Matters because for tasks like spam filtering or digit recognition, hand-coded rules become a long, brittle, unmaintainable list, whereas ML learns predictive patterns directly.

ML_CS 1 · p16, p19-20

When to Use ML

Use ML when human expertise doesn't exist (navigating Mars), humans can't explain their expertise (biometrics), the solution must be customized (personalized medicine), tasks are definable only by examples, or hidden correlations exist in large data. Do NOT "learn" tasks that are trivially computed (e.g. payroll).

ML_CS 1 · p25-26

Types of ML by Level of Supervision

Supervised (labelled feedback), Unsupervised (no feedback / no labels), and Reinforcement (delayed reward/penalty feedback). Understanding which paradigm a problem fits is the first modelling decision.

ML_CS 1 · p29

Supervised Learning — Classification

Given labelled pairs (xᵢ, yᵢ), learn f(x) to predict a categorical y (e.g. benign vs malignant). Goal: assign unseen records to a class as accurately as possible. x can be multi-dimensional (each dimension an attribute). Applications: face recognition, spam filters, fraud detection, document tagging.

ML_CS 1 · p33-37

Supervised Learning — Regression

Given labelled pairs (xᵢ, yᵢ), learn f(x) to predict a real-valued y. Goal: assign unseen records a value as accurately as possible (e.g. predicting used-car price, arctic sea-ice extent by year).

ML_CS 1 · p39

Unsupervised Learning — Clustering

Given unlabelled x₁…xₙ, output hidden structure behind the data (e.g. clustering). Goal: minimise intra-cluster distance and maximise inter-cluster distance. Techniques: k-Means, hierarchical clustering, EM; and for dim-reduction: PCA, kernel PCA, LLE, t-SNE.

ML_CS 1 · p40-42

Reinforcement Learning

A feedback-based technique where an agent learns by acting in an environment and observing results — positive feedback (reward) reinforces behaviour, negative feedback (penalty) discourages it. Suits sequential decision problems with long-term goals (game-playing, robotics). No labelled data; learning is by trial and error.

ML_CS 1 · p44-47

Semi-Supervised Learning

Combines supervised and unsupervised learning on partially labelled data — some labelled and a lot of unlabelled data (e.g. Google Photos grouping and then labelling faces).

ML_CS 1 · p50

Batch vs Mini-Batch vs Online Learning

Classified by how training data is fed: Batch uses all data per training step; Mini-batch uses a subset; Online (incremental) uses a single instance at a time. Online learning suits streaming data and continual updates.

ML_CS 1 · p51

Instance-Based vs Model-Based Learning

Instance-based compares new data points to stored known points (e.g. KNN — lazy learning). Model-based detects patterns in training data and builds a predictive model (e.g. regression). Determines memory/compute trade-off and generalisation behaviour.

ML_CS 1 · p52

Features / Attributes / Predictors

The input columns used to predict the target (e.g. CGPA, communication skills, aptitude to predict "Job Offered?"). Choosing informative features is central to model quality.

ML_CS 1 · p30-31

ML Workflow (End-to-End)

(1) Should I use ML? (is there a pattern, can I solve analytically, do I have data). (2) Gather/organise data. (3) Preprocess, clean, visualise. (4) Choose model, loss, regularization. (5) Optimize. (6) Hyperparameter search. (7) Analyse performance/mistakes and iterate. Understanding this loop frames every other topic.

ML_CS 1 · p57-58

Issues in Machine Learning

Key practical issues surveyed: what algorithm/representation to use, sufficiency and quality of data, generalisation to unseen cases, and choosing appropriate performance metrics. These motivate the workflow and evaluation modules.

Module 2 — ML Workflow & Data · source: ML_CS 2_1Aug2026.pdf

Three Components of Every ML Algorithm

Every ML algorithm = Data Representation + Parameter Optimization + Model Evaluation/Selection. A useful lens for comparing the thousands of available algorithms.

ML_CS 2 · p5

Data, Objects & Attributes

Data = a collection of data objects and their attributes. An attribute (aka variable, field, feature, dimension) is a property of an object; an object (aka record, point, sample, instance) is described by a set of attributes. This is the row/column mental model.

ML_CS 2 · p7

Attribute Types: Nominal, Ordinal, Interval, Ratio

Nominal: labels, only distinctness (=, ≠) — zip codes, eye colour. Ordinal: also ordered (<, >) — grades, rankings. Interval: meaningful differences (+, −) — Celsius dates. Ratio: meaningful ratios too (×, ÷) with true zero — Kelvin, length, counts. Determines which statistics and transformations are valid.

ML_CS 2 · p8-12

Ratio vs Interval Distinction

Only ratio scales have a true zero, so "twice as much" is meaningful. 10°C is NOT twice 5°C (interval), but 10 K IS twice 5 K (ratio). Height "above average" behaves like interval (no true zero). Exam-relevant justification pattern.

ML_CS 2 · p10

Discrete vs Continuous Attributes

Discrete: finite / countably infinite values (zip codes, counts); binary is a special case. Continuous: real-valued (temperature, height), stored as floating point. Governs modelling and encoding choices.

ML_CS 2 · p13

Characteristics of Data

Dimensionality (many attributes → challenges), Sparsity (only presence counts), Resolution (patterns depend on scale), and Size (analysis type depends on volume). These characteristics drive preprocessing decisions.

ML_CS 2 · p14

Data Quality Dimensions

Quality data is Correct, Complete, Consistent, Trustable, Interpretable and Usable-on-demand. Poor data quality directly harms ML — e.g. a loan-risk classifier built on bad data denies credit-worthy applicants and approves defaulters.

ML_CS 2 · p23-24

Noise and Outliers

Noise = extraneous objects or modification of original values (distortion). Outliers = objects considerably different from most others; they may be nuisance noise (to remove) OR the very goal of analysis (fraud, intrusion detection). Context decides which.

ML_CS 2 · p25-26

Handling Missing Values

Causes: information not collected, or attribute inapplicable. Options: eliminate the object/variable, estimate/impute the value (mean/median), or ignore it during analysis. Imputation strategy affects downstream bias.

ML_CS 2 · p27, p36

Duplicate Data & Data Cleaning

Datasets may contain duplicate or near-duplicate objects, a major issue when merging heterogeneous sources (e.g. same person, multiple emails). Data cleaning is the process of resolving these plus noisy/inconsistent/intentional-error records.

ML_CS 2 · p28, p34-35

Handling Outliers (Univariate) — IQR & 3-Sigma

Two standard rules: IQR — flag values below Q1−1.5·IQR or above Q3+1.5·IQR. 3-Sigma (Z-score) — for normal data, flag values outside μ ± 3σ (≈99% lie within). Know how to compute both by hand.

ML_CS 2 · p37-40

Data Preprocessing Steps

Preprocessing = Data Aggregation + Data Cleansing + Instance selection & partitioning + Feature tuning. It splits into data engineering (raw→prepared data) and feature engineering (prepared→model-ready features).

ML_CS 2 · p29, p31

Aggregation

Combining attributes/objects into one — for data reduction, change of scale (cities→regions, days→months), and to produce more stable, lower-variability data.

ML_CS 2 · p32-33

Sampling & Train/Validation/Test Partitioning

Sampling is the main data-reduction technique; a sample works nearly as well as the full set if representative (same properties of interest). Small samples cause sampling noise; a flawed process causes sampling bias even at large size. Data is partitioned into training, validation (evaluation) and test sets (e.g. 8000/2000/500).

ML_CS 2 · p41-44

Sampling Types

Simple random, Stratified (preserves class proportions), and Clustered sampling. Stratified matters when class balance must be maintained across splits (e.g. IRIS by species).

ML_CS 2 · p43-44

Handling Imbalanced Training Sets

Modify the training distribution so the rare class is well represented: under-sample the majority class or over-sample the rare class (e.g. SMOTE). Essential when the class of interest (fraud, cancer) is rare.

ML_CS 2 · p45

Feature Scaling — Normalization vs Standardization

Normalization (min-max): use when bounds are known and data ≈ uniform, or algorithms make no distribution assumption (KNN, NN); scales to [0,1] or [−1,1]. Standardization (z-score): use when algorithms assume Gaussian data; not range-bounded; less affected by outliers. Fit scalers on the training set only, then transform both train and test. Scaling the target is generally not required.

ML_CS 2 · p46-48

Feature Engineering

Deriving a good feature set: Extraction (dimensionality reduction), Selection (pick useful existing features, drop redundant/irrelevant/mostly-missing), Construction (combine features — polynomial expansion, feature crossing, domain logic), and Transformation (rescale/encode/discretize).

ML_CS 2 · p49-54

Curse of Dimensionality

As the number of features grows, data becomes increasingly sparse in the occupied space, hurting learning. Solution: dimensionality reduction (e.g. PCA) to create fewer, lower-dimensional features.

ML_CS 2 · p51

Discretization / Binning

Converting a continuous attribute into a discrete one ("binning"/"bucketing") — into interval labels (0-10, 11-20) or conceptual labels (youth/adult/senior). Helps Naive Bayes, decision trees, KNN; handles outliers and improves value spread. Equal-width partitions the range into N equal intervals (W=(B−A)/N; outliers can dominate); Equal-depth puts ~equal counts per bin (good scaling).

ML_CS 2 · p55-56

Encoding Categorical Features

One-Hot / Dummy encoding: maps a categorical attribute to binary indicator variables. Label encoding: maps categories to integers. Choice affects whether spurious ordinal relationships are introduced.

ML_CS 2 · p57

Inductive Learning Hypothesis

Any hypothesis that approximates the target function well over a sufficiently large training set will also approximate it well over unseen examples. This assumption is what makes generalisation from data possible. Inductive learning covers classification (discrete F(X)), regression (continuous F(X)) and probability estimation.

ML_CS 2 · p62

Hypothesis Space (General vs Specific)

A hypothesis constrains attribute values. The most general hypothesis (?, ?, …, ?) labels every instance positive; the most specific (∅, …, ∅) labels none positive. Learning searches this space for a hypothesis consistent with the data.

ML_CS 2 · p66

Core Challenges of ML

Training data problems (insufficient / non-representative), model-selection problems (overfitting / underfitting), and validation-and-testing problems. These recur through every subsequent module.

ML_CS 2 · p59

Module 3 — Linear Models for Regression · source: ML_CS 34_916 Aug 2026.pdf

Simple vs Multiple Linear Regression

Simple: one predictor (Income vs Education). Multiple: several predictors (Income from Education, Soft skills, Experience, Age). The model is linear in its parameters θ.

ML_CS 34 · p9

Hypothesis, Parameters & Model

Training set → learning algorithm → hypothesis h(·) mapping input x to predicted output. The θ's are the parameters to be learned. Central question: "How to choose the θ's?" — answered by minimizing a cost function.

ML_CS 34 · p8

Cost Function (Least Squares / MSE)

Measures how far predictions are from actual values, using squared errors. Minimizing it gives the best-fit line. Intuition built from y=θ₀ (horizontal line) to y=θ₀+θ₁x — the cost surface over parameters is bowl-shaped (convex).

ML_CS 34 · p11-19

Convex Function

A real-valued function is convex if the line segment between any two points on its graph lies on or above the graph. The MSE cost of linear regression is convex, guaranteeing a single global minimum that gradient descent can reach.

ML_CS 34 · p23

Closed-Form (Normal Equation) Solution

Solves for optimal parameters directly (analytically) by setting the gradient of the cost to zero: θ = (XᵀX)⁻¹Xᵀy. Uses vectorization (matrix form) rather than iteration. Exact but requires matrix inversion — costly for many features.

ML_CS 34 · p24-30

Vectorization

Expressing the hypothesis and cost over the whole dataset as matrix/vector operations (Xθ) rather than loops — enables the closed-form solution and efficient computation.

ML_CS 34 · p25-29

Gradient Descent

Iterative optimization: start at some θ, repeatedly step in the direction of steepest descent (negative gradient) to reduce cost until convergence. A positive derivative pushes θ down, a negative derivative pushes it up — so it always moves toward the minimum.

ML_CS 34 · p31-49

Choosing the Learning Rate

Learning rate α controls step size. Too small → very slow convergence; too large → overshoots and may diverge. It is a key hyperparameter tuned by observing whether the cost decreases each iteration.

ML_CS 34 · p50, p53

Feature Scaling & Gradient Descent

With scaling, cost contours are circular → GD path goes straight to the minimum, converges fast. Without scaling, contours are elongated → GD zig-zags inefficiently. So scale features before running GD.

ML_CS 34 · p51-52

Batch, Stochastic & Mini-Batch Gradient Descent

Batch: derivative from all data before one update (slow, stable, small datasets). Stochastic (SGD): update per single instance (fast, noisy/low-stability, online learning). Mini-batch: update per small batch (medium speed/stability, default for deep learning).

ML_CS 34 · p65-71

R-squared (Goodness of Fit)

The proportion of variation in y explained by the regression model (explained variation ÷ total variation). Measures goodness of fit for a regression model; higher is better (max 1). Used to compare regression models.

ML_CS 34 · p74

Linear Basis Function Models / Polynomial Regression

When output is a non-linear function of the input, apply basis functions Φⱼ(x) (e.g. powers of x for an M-th order polynomial). Still called "linear" because the model is linear in the weights w. Φ₀(x)=1 gives the bias term.

ML_CS 34 · p75-79

Bias and Variance

Bias = error from wrong (too-simple) assumptions → underfitting; high bias means predictions systematically far from truth. Variance = sensitivity to the particular training set → overfitting; high variance means a wiggly model that fits training noise but fails on new data.

ML_CS 34 · p80-81

Underfitting vs Overfitting

Underfitting: model too simple → high bias, low variance; both training and test error high. Overfitting: model too complex → low bias, high variance; training error very low but test error high (poor generalization). The goal is the balanced middle.

ML_CS 34 · p82-90

Ways to Handle Overfitting

(1) Increase training set size (larger data reduces overfitting, especially for higher-order models). (2) Reduce model complexity. (3) Apply regularization. Choosing model complexity is validated experimentally against test error.

ML_CS 34 · p84-88

Regularization

Adds a penalty on the size of the weights to the cost, discouraging overly complex models and controlling overfitting. Common to both linear (M3) and logistic (M4) regression. Strength is a tuned hyperparameter (λ).

ML_CS 34 · p89-95

Ridge, Lasso & Elastic Net

Ridge (L2 / Tikhonov): penalizes squared weights → shrinks weights toward (but not exactly) zero. Lasso (L1): penalizes absolute weights → can set weights exactly to 0 (sparse model, feature selection). Elastic Net: mixes L1 and L2 via ratio r (r=0→Ridge, r=1→Lasso); preferred for highly correlated features.

ML_CS 34 · p96-99

L1 vs L2 — Practical Choice

L1 drives some coefficients exactly to 0 (sparsity, automatic feature selection) but is non-differentiable so awkward for gradient methods. L2 yields small-but-nonzero weights and is differentiable. Elastic net is preferred when features are highly correlated.

ML_CS 34 · p99

Module 4 — Linear Models for Classification (Logistic Regression & Evaluation) · source: ML_CS 5 6.pdf

Generative vs Discriminative Classifiers

Probabilistic generative: learn the joint distribution P(X, Y) (e.g. Naive Bayes). Probabilistic discriminative: learn the decision boundary separating classes directly (e.g. logistic regression). Objective in classification: minimise mis-classification rate.

ML_CS 5 · p4

Logistic Regression Model

A statistical model for binary classification that predicts the probability an input belongs to a class. It computes a linear combination z=w₀x₀+…+wₙxₙ and squashes it through the logistic (sigmoid) function h(x)=1/(1+e⁻ᶻ) to output a value in [0,1].

ML_CS 5 · p7

Sigmoid / Logistic Function

Takes any real input and outputs a value between 0 and 1, giving a probability interpretation. σ(t) < 0.5 when t < 0 and σ(t) ≥ 0.5 when t ≥ 0, so the model predicts class 1 when xᵀθ ≥ 0.

ML_CS 5 · p12, p58

Why Not Linear Regression for Classification

Fitting a line and thresholding at 0.5 breaks down: predictions hθ(x) can exceed 1 or fall below 0, and least squares is highly sensitive to outliers — a single new point can swing the boundary. Logistic regression is robust to this and bounds output to [0,1].

ML_CS 5 · p8-13

Discriminant Function & Decision Rule

A discriminant f(x) takes input x and assigns it to one of K classes Cₖ. A linear discriminant f(x,w)=w₀+wᵀx gives decision rule y=sign(w₀+wᵀx); the boundary w₀+wᵀx=0 is a hyperplane. In two-class problems f(·) is binary-valued.

ML_CS 5 · p9

Decision Boundary (Linear & Non-Linear)

At the decision boundary logistic-regression output is 0.5. With linear features the boundary is a line/hyperplane; with polynomial/engineered features it becomes non-linear (curved), letting the model separate more complex class regions.

ML_CS 5 · p14-15

Logistic Regression Cost (Cross-Entropy / Log Loss)

MSE would be non-convex for logistic regression, so a log-loss cost is used: heavily penalizes confident wrong predictions (cost→∞ as prediction diverges from the true label) and is 0 when prediction matches the label. This cost is convex, so gradient descent finds the global minimum.

ML_CS 5 · p19-22

Fitting Logistic Regression via Gradient Descent

Parameters are fit by applying gradient descent to the cross-entropy cost. The update rule has the same form as linear regression (with the sigmoid hypothesis substituted). Prediction for new x uses hθ(x) and a 0.5 threshold.

ML_CS 5 · p22-24, p28

Odds Ratio & Coefficient Interpretation

The exponential of a regression coefficient, e^w, is the odds ratio for a one-unit increase in that predictor. E.g. odds of a job offer increase by a factor of 1.35 for each unit increase in CGPA. Enables interpretable inference from logistic models.

ML_CS 5 · p29

Logit / Log-Odds

logit(p) = log(p/(1−p)) is the inverse of the logistic function; applied to the estimated probability it returns t = xᵀθ. Also called log-odds — it linearizes the relationship between features and the log of the odds.

ML_CS 5 · p58

Regularization in Logistic Regression (parameter C)

Same regularization idea as linear regression. In Scikit-Learn's LogisticRegression the strength is controlled by C (the inverse of α): higher C → less regularization (more overfitting risk), lower C → stronger regularization.

ML_CS 5 · p30-31

Confusion Matrix

A table of predicted vs actual classes with TP, FP, FN, TN. It is the basis for all classification metrics and reveals what a single accuracy number hides (which class the errors fall on).

ML_CS 5 · p33-36

Accuracy Limitation & Class Imbalance

Accuracy is misleading under imbalance: a model predicting the majority class for everything can score 99% yet detect zero rare-class cases. Since detecting the rare class (fraud, cancer, defects) is usually the point, use precision/recall/ROC instead. Accuracy is most meaningful when classes are balanced.

ML_CS 5 · p34-35, p50

Precision, Recall (TPR) & F1

Precision = TP/(TP+FP) (of predicted positives, how many correct). Recall/TPR = TP/(TP+FN) (of actual positives, how many caught). F1 is their harmonic mean, balancing both. Choose based on which error is costlier.

ML_CS 5 · p44

Cost of FP vs FN (Choosing a Model)

Different mistakes carry different costs: disease screening wants a low false-negative rate (don't miss sick patients); spam filtering wants a low false-positive rate (don't drop real mail). The same application may need conservative vs aggressive threshold settings.

ML_CS 5 · p40

ROC Curve

Plots True Positive Rate against False Positive Rate as the decision threshold varies, showing the detection-rate vs false-alarm trade-off. Corners: (0,0) declare all negative, (1,1) declare all positive, (1,0) ideal; the diagonal = random guessing; below diagonal = worse than random.

ML_CS 5 · p41-43

Constructing an ROC Curve

Use a classifier that outputs a continuous score; sort instances by decreasing score; apply a threshold at each unique score; count TP/FP/TN/FN and plot (FPR, TPR) at each. Higher-scored instances are more likely positive.

ML_CS 5 · p44-45

AUC (Area Under ROC)

AUC measures a model's ability to separate classes: AUC=1 is a perfect model, AUC=0.5 is random. Higher AUC = better average performance. Used for threshold selection and model comparison; when no model dominates everywhere, one may be better at low FPR and another at high FPR.

ML_CS 5 · p42, p46

Solutions to Class Imbalance

(1) Generate synthetic minority samples (SMOTE — new points from distances to nearest neighbours). (2) Change the metric to recall/precision/ROC rather than accuracy. (3) Try algorithms that handle imbalance better (SVM, tree-based).

ML_CS 5 · p50-51

Multiclass Classification — OvA vs OvO

One-vs-All (One-vs-Rest): train N binary classifiers, one per class vs the rest; pick the highest-scoring. One-vs-One: train N(N−1)/2 classifiers for every class pair and vote. Scikit-Learn defaults to OvA (OvO for SVMs).

ML_CS 5 · p56-57

Module 5 — Exam-Referenced Topics (post-midsem & EC prerequisites) · source: EC2 & EC3 instruction sheets

k-Nearest Neighbors (kNN)

An instance-based (lazy) classifier: to classify a new point, find its k nearest training points (by a distance metric such as Euclidean or Manhattan) and take the majority class vote. Low k (1-2) → sensitive to noise, low bias / high variance; high k (10-20) → smoother, higher bias / lower variance.

EC3 · Q1

Bayes' Theorem & Naive Bayes

Bayes' theorem updates the probability of a class given evidence: P(class|data) ∝ P(data|class)·P(class). Naive Bayes assumes features are conditionally independent given the class, multiplying per-feature likelihoods — used for medical-test posteriors and the "play cricket?" weather classifier.

EC3 · Q2, Q3

Maximum Likelihood Estimation (MLE)

Estimates a parameter (e.g. coin-bias p) by maximizing the likelihood of the observed i.i.d. data, usually via the log-likelihood for tractability. For a coin with h heads in n tosses, the MLE is p̂ = h/n.

EC3 · Q3

Decision Trees — Entropy, Information Gain, Gini

Trees split on the attribute that best reduces impurity. Entropy measures class disorder; Information gain is the entropy reduction from a split (pick the highest). Gini index = 1−Σpᵢ² is an alternative impurity measure. Continuous attributes are split at a threshold (e.g. the mean).

EC2 · Q6

Support Vector Machines (SVM)

Finds the maximum-margin separating hyperplane defined by support vectors, Lagrange multipliers and labels. Non-linearly-separable data is handled via the kernel trick (e.g. polynomial kernel K(u,v)=(u·v+1)²) that maps points into a higher-dimensional space where they become separable.

EC3 · Q4

K-Means vs Gaussian Mixture Models

K-Means: assign each point to the nearest centroid, then recompute centroids as cluster means, iterating (hard assignments). GMM: models data as a mixture of Gaussians with mixing weights and gives soft "responsibilities" (probabilities). GMM handles elliptical/overlapping clusters K-Means cannot.

EC3 · Q5

Ensemble Learning — Bagging, Random Forest, Boosting

Bagging: train models on bootstrap samples and average/vote; unused rows form the Out-Of-Bag set for validation. Random Forest: bagged trees that also randomly subsample features at each split (extra decorrelation). AdaBoost: sequentially reweights instances — up-weighting misclassified ones — and combines weak learners by weight α; final label = sign(Σ αₜ·predictionₜ).

EC3 · Q6

AI vs Data Science vs Machine Learning

A nested relationship: Data Science is the broad umbrella (collection, preparation and analysis of data, leveraging AI/ML, research and statistics for business decisions); Artificial Intelligence sits inside it (technology for machines to understand/interpret, learn and make "intelligent" decisions); and Machine Learning is a subset of AI (algorithms that improve through supervised, unsupervised and reinforcement learning). So ML ⊂ AI ⊂ Data Science.

ML_CS 1 · p11 (image)

ML Algorithmic Trade-Off (Interpretability vs Accuracy)

Algorithms trade interpretability against accuracy. High-interpretability / lower-accuracy: Linear/Logistic Regression, Lasso, Decision Trees, Naive Bayes. High-accuracy / lower-interpretability: Random Forests, Boosting, SVMs, Neural Nets / Deep Learning. Choose based on whether an explainable model or raw predictive performance matters more for the problem.

ML_CS 1 · p46 (image)

Imputing Missing Values — Methods

Beyond deleting records, a missing cell can be filled by: replace with a constant (e.g. 0), forward-fill with the last known value, replace with the column mean, or interpolate (e.g. spline interpolation) between neighbouring known values. Each strategy trades simplicity against introduced bias.

ML_CS 2 · p36 (image)

Maxima & Minima Condition (Optimisation)

At a maximum or minimum of a differentiable function the slope is zero: dy/dx = tan(0°) = 0 — the tangent is parallel to the x-axis. This stationary-point condition is exactly what the normal equation (∂J/∂θ = 0) and gradient descent exploit to locate the cost minimum.

ML_CS 34 · p27 (image)

Non-Invertible XᵀX (Pseudo-Inverse)

The normal equation θ = (XᵀX)⁻¹Xᵀy needs XᵀX to be invertible. If it is singular — redundant / linearly-dependent features, or more features than examples (d > n) — you can: use the pseudo-inverse (Python: numpy.linalg.pinv), remove redundant features, or drop extra features so that d ≤ n.

ML_CS 34 · p30 (image)

Closed-Form vs Gradient Descent

Gradient descent: iterative, must choose learning rate α, works well when n is large, and supports incremental/online learning. Closed-form (normal equation): non-iterative and needs no α, but slow when features are many because computing (XᵀX)⁻¹ is roughly O(n³). Use GD for large/streaming data, closed-form for small feature sets.

ML_CS 34 · p64 (image)

Early Stopping (Handling Overfitting)

Track the validation-set error (e.g. RMSE) while training epoch by epoch and keep the model at the point of minimum validation error ("best model") — before it starts rising again while training error keeps falling. Stopping there prevents the model from over-learning training noise.

ML_CS 34 · p89 (image)

Binary vs Multiclass Classification

Classification is categorised by its output labels. Binary: two classes (e.g. spam vs ham). Multiclass: three or more mutually-exclusive classes (e.g. Enjoy-Sports = Yes/No/Maybe). Multiclass problems are commonly reduced to several binary problems via One-vs-All or One-vs-One.
