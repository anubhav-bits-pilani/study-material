M1 · Introduction to Machine Learning · 14 items

Learning as improving with experience

A program learns if its performance \(P\) at task \(T\) improves with experience \(E\); naming all three turns a vague goal into a well-posed problem (spam filtering: \(T\) = label emails, \(P\) = percentage correctly classified, \(E\) = labelled emails). Changing \(P\) changes what "better" means, so two formulations of one problem can favour different models.

1.1.1 · slides 15–17

Traditional programming versus the ML paradigm

Traditional programming feeds data and a hand-written program to the computer to get output; ML feeds data and the desired output to get the program. The slides' spam example shows why: a hand-coded rule list ("4U", "free") becomes long and hard to maintain, while a learned filter is shorter, easier to update and usually more accurate.

1.1.1 · slides 15, 18–19

When to use ML, and when not to

Use ML when human expertise does not exist (navigating on Mars), when experts cannot explain it (recognising a handwritten 2 versus 7), or when the model must be personalised. Do not use it when an exact closed-form rule already exists: there is no need to "learn" payroll.

1.1.2 · slides 22–25

Application domains

ML powers vision (object detection, self-driving cars), language (assistants, chatbots), recommendation (Amazon, Netflix), security and fraud detection. Recognising the task type behind an application (classification, regression, clustering, sequential decision) is the first modelling step.

1.1.3 · slides 11–13, 20–21

Supervised learning: classification versus regression

Supervised learning learns \(f(x)\) from labelled pairs \((x_i, y_i)\). If \(y\) is discrete (benign/malignant, job offered yes/no) the task is classification; if \(y\) is real-valued (used-car price, sea-ice extent) it is regression. Encoding classes as numbers does not turn classification into regression.

1.2.1 · slides 27–36

Unsupervised learning

Unsupervised learning gets only \(x_1, \dots, x_n\) and outputs hidden structure, most often clusters. The goal is to minimise intra-cluster distances and maximise inter-cluster distances, as in splitting a retailer's customers into big and low spenders.

1.2.2 · slides 37–40

Reinforcement learning

An agent acts in an environment and receives delayed reward or penalty instead of a label, learning by trial and error to make a sequence of decisions (a robot dog learning to walk). The feedback signal (labels, none, delayed reward) is what separates supervised, unsupervised and reinforcement learning.

1.2.3 · slides 41–46

Semi-supervised learning

Combines a small labelled set with a large unlabelled set (Google Photos: you name a few faces, it labels the rest). It only helps if the unlabelled data's structure (clusters, smoothness) agrees with the labels.

1.2.4 · slide 47

Batch, mini-batch and online learning

Batch learning trains on all data at once, mini-batch on subsets, online (incremental) on one instance at a time. Online learning suits streams and drifting data (fraud patterns), but a large learning rate makes it forget old data quickly.

1.3.1 · slide 48

Instance-based versus model-based learning

Instance-based (lazy) learners store the training data and compare each new point to it at query time (k-NN); model-based (eager) learners fit parameters once and then discard the data (linear regression). Lazy learners pay little to train and a lot per query; eager learners the reverse.

1.3.2 · slide 49

The inductive learning hypothesis

Any hypothesis that approximates the target function well over a sufficiently large set of training examples will also approximate it well on unobserved examples. This is the assumption that lets training performance stand in for generalisation, and it fails if the training data are small or unrepresentative.

1.4.1 · slides 119–122

Hypothesis space: most general and most specific

In the EnjoySport representation \((?, \text{Cold}, \text{High}, ?, ?, ?)\) is one hypothesis; \((?, ?, ?, ?, ?, ?)\) is the most general (every day positive) and \((\varnothing, \dots, \varnothing)\) the most specific (no day positive). Restricting the hypothesis space is an inductive bias, and without some bias a learner cannot generalise beyond the data it memorised.

1.4.2 · slide 123

Three inductive tasks

Given examples \((X, F(X))\), inductive learning predicts \(F(X)\) for new \(X\): classification when \(F\) is discrete, regression when continuous, and probability estimation when \(F(X)\) is a probability. The output type fixes the loss and the evaluation metric.

1.4.3 · slides 119, 130

The ML workflow

Decide whether ML fits, gather and organise data, preprocess and explore it, choose a model, loss and regulariser, optimise, tune hyper-parameters, then analyse errors and iterate. The final test-set evaluation measures generalisation and comes last.

M2 · Machine Learning Workflow · 17 items

Objects and attributes

A data set is a collection of objects (records, samples, instances) described by attributes (features, variables, dimensions). Every ML algorithm then has three parts: data representation, parameter optimisation, and model evaluation and selection.

2.1.1 · slides 62–64

Measurement levels decide the legal operations

Nominal values only support \(=, \ne\); ordinal adds order \(<, >\); interval adds meaningful differences \(+, -\); ratio adds a true zero, so \(\times, \div\) are meaningful. So \(10\,{}^\circ\text{C}\) is not "twice as hot" as \(5\,{}^\circ\text{C}\) (Celsius is interval), but 10 K is twice 5 K (Kelvin is ratio).

2.1.2 · slides 65–69

Discrete versus continuous attributes

Discrete attributes take finitely or countably many values (zip codes, counts, words), with binary as a special case; continuous attributes take real values (height, temperature) recorded to finite precision. Measurement level and discreteness are separate axes: a zip code is discrete and nominal.

2.1.3 · slide 70

Dimensionality, sparsity, resolution and size

High dimensionality brings the curse of dimensionality; sparse data (document-term matrices, transactions) are mostly zeros, so only presence counts and only non-zeros are stored; patterns depend on resolution (scale of measurement); and data size limits which analyses are practical.

2.1.4 · slides 71–78

Data-quality problems

Noise distorts values, outliers differ markedly from the rest, wrong or fake data are errors (Salary = −10), missing values are blanks, and duplicates arise when sources are merged. The slides' tax table asks "a mistake or a millionaire?" about a 10000K income: an outlier is noise in one analysis and the target in another (fraud, intrusion detection).

2.2.1 · slides 80–85, 91–92

Handling missing values

Eliminate the affected objects or attributes, estimate (impute) the value by mean, median, mode or a class-conditional statistic, or ignore it during analysis. Imputation statistics must come from the training split only, or information leaks from the test set.

2.2.2 · slides 84, 93

Data aggregation

Combining attributes or objects into one (days into weeks, cities into regions) reduces data, changes scale and gives more stable values, because the mean of \(m\) independent values has variance \(\sigma^2/m\). The price is lost detail.

2.2.3 · slides 88–90

IQR outlier rule

Flag values outside \([Q_1 - 1.5\,\text{IQR}, \ Q_3 + 1.5\,\text{IQR}]\). For the slide data 10, 11, 11, 11, 12, 12, 13, 14, 14, 15, 17, 22: \(Q_1 = 11\), \(Q_3 = 14.5\) (median of halves), \(\text{IQR} = 3.5\), fences \(5.75\) and \(19.75\), so 22 is the outlier. Quartile conventions differ, so state the one you use.

2.3.1 · slides 94–96

The 3σ rule

For roughly normal data, values outside \(\mu \pm 3\sigma\) are outliers, since 99.7% of a normal lies inside (\(\mu = 50, \sigma = 5\) gives fences 35 and 65). On skewed data the outliers inflate \(\mu\) and \(\sigma\) themselves, so the IQR rule is safer.

2.3.2 · slide 97

Why three data sets

The training set fits parameters, the validation set chooses hyper-parameters and models, and the test set estimates generalisation once at the end. A sample works almost as well as the full data only if it is representative; small samples add sampling noise and flawed sampling adds bias even at large sizes.

2.4.1 · slides 98–100, 116

Simple random, stratified and cluster sampling

Simple random sampling can unbalance classes: splitting 150 Iris flowers 2/3 to 1/3 gave a test set of 12 Setosa, 22 Versicolor and 16 Virginica instead of 50/50/50 proportions. Stratified sampling keeps each class's share in every split; cluster sampling draws whole groups.

2.4.2 · slides 99–101

Imbalanced training sets

When the rare class matters, change the training distribution: undersample the majority (throws data away) or oversample the minority, by duplication or by SMOTE's synthetic points between minority neighbours (risk of overfitting). Resample only the training split, after splitting.

2.4.3 · slide 102

Feature scaling: normalisation versus standardisation

Min-max normalisation maps to \([0, 1]\) and suits bounded, roughly uniform features and distribution-free methods (k-NN, neural nets); z-score standardisation suits methods that assume Gaussian data and is less hurt by outliers. With income from 12,000 to 98,000, the value 73,000 maps to \(0.709\); with \(\mu = 54{,}000\), \(\sigma = 16{,}000\) its z-score is \(1.19\). Target values generally are not scaled.

2.5.1 · slides 103–105

Feature extraction, selection, construction and transformation

Extraction builds fewer new features (PCA), selection keeps a useful subset (drop irrelevant, redundant or mostly-missing columns), construction combines features (polynomial terms, feature crossing, domain logic), and transformation re-expresses them (semester totals into GPAs, or completion flags).

2.5.2 · slides 106–111

Discretisation: equal-width versus equal-depth

Binning turns a continuous attribute into intervals, which Naïve Bayes and trees often prefer and which tames outliers. Equal-width bins have width \(W = (B - A)/N\) but outliers leave most bins empty; equal-depth bins hold about the same number of records each and handle skew.

2.5.3 · slides 112–113

Encoding categorical features

One-hot (dummy) encoding maps a category to binary indicator columns; label encoding maps it to integers. Label encoding imposes a fake order and spacing, so use it only for ordinal data or trees.

2.5.4 · slide 114

Curse of dimensionality (first look)

As dimensions grow, data become sparse in the space they occupy: to capture 10% of uniform data in 10 dimensions a sub-cube needs edge \(0.1^{1/10} \approx 0.79\) of each axis. Dimensionality reduction such as PCA is the remedy.

2.5.5 · slide 108
M3 · Linear Models for Regression · 18 items

Simple versus multiple linear regression

Simple regression predicts \(y\) from one feature (income from education); multiple regression uses several (education, soft skills, experience, age) in \(h_\theta(x) = \theta^\top x\) with \(x_0 = 1\). Each \(\theta_j\) is the change in \(\hat{y}\) per unit of \(x_j\) with the others held fixed.

3.1.1 · slides 131–133

Cost function as the fit criterion

Residuals are the vertical gaps between actual and predicted values; the cost \(J(\theta)\) sums or averages their squares (SSE, MSE). The slides compare three mileage-price lines by their training error and keep the smallest: learning means choosing \(\theta\) to minimise \(J\).

3.1.2 · slides 135–146

Convexity of the squared-error cost

A function is convex if the chord between any two points lies on or above its graph. The squared-error \(J(\theta)\) of linear regression is a convex bowl (its Hessian \(X^\top X/n\) is positive semi-definite), so every local minimum is the global one.

3.1.2, 3.3.5 · slides 147, 172–173

Closed-form solution versus gradient descent

Setting \(\nabla J = 0\) gives the normal equations \(\theta = (X^\top X)^{-1} X^\top y\): one exact step with no learning rate, no scaling and no iterations. It needs \(X^\top X\) invertible (no perfectly collinear features, enough rows) and costs about \(O(d^3)\), so gradient descent, which needs \(\eta\), iterations and scaling, wins with very many features and for models with no closed form (logistic regression).

3.2.1 · slides 148–154, 188

Gradient descent update

Repeatedly step against the gradient: \(\theta_j \leftarrow \theta_j - \eta\,\partial J/\partial\theta_j\), updating all \(\theta_j\) simultaneously from the same old values. Batch GD sums the error times feature over every example before each update, as in the slides' heart-disease example (\(\eta = 0.02\), three patients).

3.3.1 · slides 155–171, 178–187

Choosing the learning rate

Too small an \(\eta\) makes descent slow; too large makes it oscillate or diverge, with the cost rising. Diagnose \(\eta\) from the cost-versus-iteration curve: a smooth decrease that flattens is right.

3.3.2 · slides 174, 177

Feature scaling and the descent path

With unscaled features the cost contours are elongated, so the path zig-zags and converges slowly; with scaled features they are nearly circular and the path heads straight to the minimum. Scaling changes the path and the number of iterations, not the minimiser.

3.3.3 · slides 175–176

Batch, mini-batch and stochastic gradient descent

Batch GD computes the gradient from all examples per update, mini-batch from small groups, SGD from one example at a time. SGD is cheap and noisy and makes \(n\) updates per epoch; batch GD is smooth but makes one; mini-batch sits between.

3.3.4 · slides 189–194

Convergence guarantee

On a convex cost, a positive derivative moves \(\theta\) down and a negative one moves it up, so each small enough step lowers \(J\) until the gradient is zero at the global minimum. The guarantee needs a small enough \(\eta\); it does not hold for arbitrary step sizes.

3.3.5 · slides 172–173

Linear basis-function models

Replacing \(x\) by fixed basis functions \(\phi_j(x)\) (powers \(x^j\) for polynomial regression, Gaussian bumps) lets a model curve in \(x\) while staying linear in the weights, so the same normal equations and gradient descent apply.

3.4.1 · slides 198–202

Bias, variance, underfitting and overfitting

Bias is error from wrong assumptions (too simple a model); variance is error from sensitivity to the training sample (too flexible a model). Underfitting shows as high training and test error; overfitting as low training but high test error, like a degree-300 polynomial fitted to a quadratic target. Remedies for overfitting: more data, a simpler model, regularisation.

3.4.2 · slides 203–211

Regularisation

Add a penalty on weight size to the cost so the model cannot fit noise with huge coefficients. The regularisation constant \(\lambda\) trades fit for simplicity: too little leaves overfitting, too much underfits, so tune it on validation data.

3.5.1, 3.5.2 · slides 212–218

Ridge (L2) regularisation

Ridge adds \(\lambda \sum w_j^2\), which shrinks all weights smoothly but never exactly to zero. In gradient descent each step multiplies the weight by \((1 - \eta\lambda)\) before the usual update (the slide's factor 0.9).

3.5.1 · slide 219

Lasso (L1) regularisation

Lasso adds \(\lambda \sum \lvert w_j \rvert\), which pushes weights towards zero by a fixed amount each step and can set them exactly to zero, giving a sparse model and built-in feature selection. Its penalty is not differentiable at 0, so only a subgradient is available there.

3.5.2 · slides 220, 222

Elastic Net

Elastic Net mixes the L1 and L2 penalties with a ratio \(r\), keeping Lasso's sparsity while sharing weight across groups of correlated features. In sklearn's l1_ratio, \(r = 1\) is Lasso and \(r = 0\) is Ridge; the slide's wording swaps these.

3.5.3 · slides 221–222

Effect of regularisation on a gradient step

All three updates share the same data gradient and differ only in the extra pull towards zero: ridge multiplies each weight by \((1 - \eta\lambda)\) (the slide's 0.9), so its pull is proportional to \(\lvert w_j \rvert\); lasso subtracts \(\eta\lambda\operatorname{sign}(w_j)\), the same pull for every non-zero weight. The intercept is never penalised. Erratum: the slide's Lasso answer (0.1477, 0.2793) comes out larger than its unregularised weights (0.0477, 0.1793) and never states the L1 update, so do not use it as a template.

3.5.4 · slides 223–224

R² and the sum-of-squares split

\(R^2\) is the share of the variation in \(y\) explained by the model, \(1 - \text{SSE}/\text{SST}\), with \(\text{SST} = \text{SSR} + \text{SSE}\) for least squares with an intercept on training data. Training \(R^2\) never falls when a feature is added, even a random one, so it cannot pick models on its own.

3.6.1 · slides 136, 197

In-sample versus unseen-data error

Training MSE is optimistic; what counts is MSE on unseen data. The slides compare a quadratic and a linear car-price model on held-out mileage values, and raising the polynomial degree in the lab shows training error falling while test error eventually rises.

3.6.2 · slides 196, 225
M4 · Linear Models for Classification (Logistic Regression) · 12 items

Why least squares fails as a classifier

A straight line fitted to 0/1 labels (job offered against CGPA) outputs values below 0 and above 1, which are not probabilities. It is also highly sensitive to new or extreme points: adding correctly labelled points far to one side drags the line and moves the 0.5 threshold, misclassifying points that were right before.

4.1.1 · slides 232–237

The sigmoid and the 0.5 boundary

A linear classifier scores \(z = w_0 + w^\top x\) and predicts by its sign; logistic regression squashes \(z\) with the sigmoid \(\sigma(z) = 1/(1 + e^{-z})\) into \((0, 1)\), read as \(P(y = 1 \mid x)\). Since \(\sigma(z) \ge 0.5\) exactly when \(z \ge 0\), the decision boundary \(w_0 + w^\top x = 0\) is still a hyperplane; non-linear boundaries need non-linear features (e.g. squares of CGPA and IQ).

4.1.2 · slides 231, 233, 236–239

Cross-entropy (log-loss) cost

Each example costs \(-\log h\) if \(y = 1\) and \(-\log(1 - h)\) if \(y = 0\): zero for a confident correct prediction and unbounded for a confident wrong one. Squared error composed with the sigmoid is non-convex, while log-loss is convex, so gradient descent finds the global minimum.

4.2.1 · slides 241–246

Gradient descent for logistic regression

The update \(w_j \leftarrow w_j - \eta \frac{1}{m}\sum (h(x_i) - y_i)x_{ij}\) looks identical to linear regression, with only \(h\) changed to the sigmoid. There is no closed form, so iterate; unscaled features (raw IQ values) saturate the sigmoid and stall the iterations, as the slide's exercise warns.

4.2.2 · slides 246, 248, 252

Odds ratio interpretation

The log-odds \(\ln\frac{p}{1 - p}\) is linear in the features, so a one-unit rise in \(x_j\) multiplies the odds by \(e^{w_j}\). With \(z = 0.4 + 0.3\,\text{CGPA} - 0.45\,\text{IQ}\), the candidate \((5, 6)\) gets \(h = \sigma(-0.8) = 0.31\), predicted "No", and each extra CGPA point multiplies the odds of an offer by \(e^{0.3} \approx 1.35\).

4.2.3 · slides 253, 282

Regularising logistic regression: the C knob

Regularisation works exactly as in Module 3, but sklearn's LogisticRegression uses \(C = 1/\alpha\): the higher \(C\), the weaker the regularisation and the closer the fit to the training data. On perfectly separable data an unregularised model's weights grow without bound.

4.3 · slides 254–255

Confusion matrix and its metrics

The confusion matrix counts TP, FN, FP, TN for the class of interest. Accuracy is the overall hit rate, precision asks "of those flagged, how many are real?", recall asks "of the real ones, how many were caught?", and F1 is their harmonic mean, dragged towards the smaller of the two.

4.4.1 · slides 256–260

Different mistakes, different costs

Model 1 (FPR 41%, FNR 3%) suits disease screening, where a missed case is costly; Model 2 (FPR 5%, FNR 25%) suits spam filtering, where a false alarm is costly. The same application may need a conservative and an aggressive setting, which is a choice of threshold.

4.4.1, 4.4.3 · slides 261–264

The accuracy paradox

On imbalanced data a classifier can reach 99% accuracy by always predicting the majority class while catching none of the rare cases. Compare every model with that majority baseline and report recall, precision, F1 or AUC instead.

4.4.2 · slides 259, 274

ROC curve and AUC

Sort cases by score, sweep the threshold from high to low and plot \(TPR\) against \(FPR\): each positive steps up, each negative steps right. AUC measures separability, the probability that a random positive outscores a random negative: 1 is perfect, 0.5 is random guessing. Crossing curves (M1 better at low FPR, M2 at high FPR) mean neither model dominates.

4.4.3 · slides 265–272

Handling class imbalance

Three levers: resample the training data (undersample, oversample, or generate synthetic minority points with SMOTE), change the performance metric (recall, F1, AUC instead of accuracy), and choose an algorithm or threshold that weights the rare class.

4.4.4 · slide 275

Multiclass: One-vs-All and One-vs-One

OvA trains one binary classifier per class (class \(k\) against the rest) and predicts the highest score; OvO trains \(K(K - 1)/2\) pairwise classifiers and takes a majority vote. sklearn applies one of them automatically when a binary algorithm meets a multiclass target.

4.5 · slides 278–281
M5 · Decision Tree Classifier · 15 items

Tree anatomy

The root node has no incoming edge, each internal node tests one attribute and has one incoming and two or more outgoing edges, and each leaf has one incoming edge and holds a class label. Classifying a record means following tests from the root to a leaf.

5.1.1 · slides 287–290, 294

A tree as a disjunction of conjunctions

Each root-to-leaf path is a conjunction of attribute tests and the tree is the disjunction of the "Yes" paths: PlayTennis = (Outlook = Sunny ∧ Humidity = Normal) ∨ (Outlook = Overcast) ∨ (Outlook = Rain ∧ Wind = Weak). Any Boolean function can be written this way, though some (XOR, parity) need large trees.

5.1.1 · slide 296

Hunt's algorithm and ID3

Grow the tree recursively: if a node is pure make it a leaf; otherwise pick the best attribute test, split, and recurse on each child with the remaining attributes. Stop when all records share a class, when no attributes remain (label by majority vote), or when a branch has no records (use the parent's majority).

5.1.2 · slides 292–293, 297, 315, 322–323

Impurity and entropy

Impurity measures how mixed the class labels in a node are. Entropy is 0 for a pure node and maximal for an even mix (1 bit for two classes); the EnjoySport target with 3 Yes and 1 No has \(E(3, 1) = 0.811\).

5.2.1 · slides 300–303

Information gain

Gain is the expected reduction in entropy from splitting on an attribute. For PlayTennis (9 Yes, 5 No, entropy 0.940) the root gains are Outlook 0.247, Humidity 0.151, Wind 0.048, Temperature 0.029, so Outlook goes at the root; under Sunny, Humidity gains the full 0.971 and makes both children pure.

5.2.1 · slides 304–313, 317–321

Gini index

Gini \(= 1 - \sum p_i^2\) is 0 for a pure node and at most 0.5 for two classes; CART picks the split with the lowest weighted child Gini. Splitting on Home Owner gives children with Gini 0 and 0.490, a weighted Gini of \(0.7 \times 0.490 = 0.343\), the best candidate along with one Marital Status grouping.

5.2.2 · slides 327, 330–332

Classification error as impurity

Error \(= 1 - \max_i p_i\) is the least sensitive impurity: if the majority class stays the same in every child, the error gain is 0 even when entropy and Gini show a real improvement. That is why trees grow with Gini or entropy.

5.2.3 · slide 338

Gain ratio and split information

Information gain favours attributes with many values: Customer ID makes every child pure and gets the highest gain while being useless for new customers. Split information (the entropy of the partition sizes, \(\log_2 n\) for an ID) penalises such fragmentation, and the gain ratio Gain/SplitInfo ranks Car Type above Customer ID.

5.2.4 · slides 339–343

Splitting continuous attributes

Sort the values and test candidate thresholds at midpoints between adjacent values (Annual Income: 55, 65, 72, …), creating a Boolean test \(A < c\). Evaluate each binary split's gain or Gini and keep the best; only midpoints where the class changes can win.

5.2.5 · slides 333–337

Overfitting in trees

As the tree grows, training error keeps falling while test error eventually rises: deep branches memorise noise, as when one noisy PlayTennis example forces a new split under Sunny ∧ Normal. A tree with 100% training accuracy is a warning sign, not a goal.

5.3.1 · slides 344–352

Pre-pruning

Stop growing early with a stopping condition: a gain threshold (the slide prunes nodes with gain \(\le 0.85\)), a minimum number of samples per node, or a maximum depth. It is cheap but can stop too soon, since a split with no gain now may enable good splits later.

5.3.2 · slides 353–356

Post-pruning

Grow the tree fully, then scan bottom-up and replace a subtree by a leaf whenever validation error does not get worse. Training accuracy drops slightly and test accuracy usually improves.

5.3.3 · slides 357–359

MDL principle and Occam's razor

Occam's razor prefers the shortest hypothesis that fits the data reasonably well. MDL makes this precise: minimise the bits to encode the tree plus the bits to encode its misclassified records (an event of probability \(p\) costs \(-\log_2 p\) bits), so a smaller tree with a few errors can beat a large perfect one.

5.3.4 · slides 360–365

CART

CART (Classification and Regression Trees) always makes binary splits and handles both tasks: classification trees split by Gini and predict the majority class, regression trees split by variance (SSE) reduction and predict the leaf mean. A nominal attribute with \(k\) values has \(2^{k-1} - 1\) binary groupings to try.

5.4 · slides 291, 327–328

Strengths, weaknesses and applications of trees

Trees are cheap to build, very fast to apply, easy to read when small, need no feature scaling and tolerate irrelevant attributes. They are unstable (one record can change the root), greedy growth may miss the best tree in an exponentially large space, each boundary involves a single attribute (axis-parallel), and unpruned trees overfit. They suit attribute-value data with discrete outputs, disjunctive concepts and noisy or missing values.

5.5 · slides 316, 366
M6 · Instance-Based Learning (K-Nearest Neighbour) · 15 items

Lazy versus eager learners

An instance-based (lazy) learner just stores \(\langle x_i, f(x_i) \rangle\) and defers all work to query time: "if it walks like a duck and quacks like a duck, it's probably a duck". Training is instant, but every prediction scans the stored data, so queries are slow and memory-hungry; eager learners fit a model once and answer queries fast.

6.1 · slides 373–376

Minkowski family of distances

Distance methods work from the dissimilarity matrix, an \(n \times n\) triangular table of pairwise distances built from the \(n \times p\) data matrix. In the Minkowski family, order \(h = 1\) gives Manhattan (city-block; Hamming for bit vectors), \(h = 2\) Euclidean, \(h \to \infty\) the supremum (largest coordinate gap); for any pair \(d_\infty \le d_2 \le d_1\), and the nearest neighbour can change with \(h\).

6.2, 6.2.1 · slides 378, 382–384

Nominal and binary dissimilarity

For nominal attributes use simple matching, the fraction of attributes that differ. For binary attributes, symmetric ones (gender) count 0–0 matches; asymmetric ones (test results, where only a positive is informative) ignore 0–0 matches, which gives the Jaccard-based distance.

6.2.2 · slides 379–381

Ordinal variables

Replace each value by its rank and map ranks to \([0, 1]\) with \((r - 1)/(M - 1)\), then treat the result as numeric. Poor, Average, Good, Excellent become \(0, \tfrac{1}{3}, \tfrac{2}{3}, 1\).

6.2.3 · slide 386

Gower distance for mixed types

Compute a per-attribute dissimilarity in \([0, 1]\) (range-scaled gap for numeric, 0/1 mismatch for nominal, rank gap for ordinal), then take a weighted average, skipping missing values and 0–0 asymmetric binaries. The slide weights Department, Satisfaction and Age as 0.3, 0.3 and 0.4, with age range \(30 - 20 = 10\).

6.2.4 · slides 387–391

Standardise before measuring distance

Without scaling, the attribute with the largest numeric range (income in rupees against age in years) decides every distance, and the nearest neighbour can flip once features are z-scored or min-max scaled. Scale query points with the training statistics.

6.2.5 · slides 385, 391

The k-NN algorithm

Find the \(k\) training points closest to the query; for a discrete target take the majority class, for a real target take the mean of the neighbours' values. There is no training phase, and 1-NN always has zero training error, which says nothing about test error.

6.3.1 · slides 375–377, 393

Choosing k

A starting rule is \(k \approx \sqrt{N}\); then plot validation error against \(k\) and take the elbow. In the slides' example (\(N = 100\), 60% class A), \(k = 1\)–3 overfits noise (high variance), the elbow at \(k = 7\) is the sweet spot, and as \(k \to N\) the model always predicts A, giving a flat 40% error (high bias).

6.3.2 · slides 394–396

Distance-weighted k-NN

Weight each neighbour's vote by a kernel of its distance, such as \(1/d^2\), \(1/(d_0 + d)^2\) or \(\exp(-(d/\sigma_0)^2)\), so close neighbours count more and a few very near points can overturn a plain majority. With weighting, all training points can be used without choosing \(k\).

6.3.3 · slides 397–401

Curse of dimensionality for nearest neighbours

k-NN uses all attributes, so if the target depends on only a few of many attributes, truly similar instances can be far apart in the full space. In high dimensions all pairwise distances become nearly equal and "nearest" loses meaning; select features or reduce dimension first.

6.3.4 · slide 392

Locally weighted regression

Instead of one global fit, fit a fresh (usually linear) model around each query point, with every training example's error weighted by a kernel of its distance from the query. The local model is used for that one prediction and then discarded.

6.4.1 · slides 403–408

Kernel-weighted gradient update

The local model is fitted by the usual delta rule with each residual multiplied by its kernel weight, \(w_j \leftarrow w_j + \eta \sum K(d)\,(f(x) - \hat{f}(x))\,a_j(x)\). The slides' 5-NN price example uses a Gaussian kernel with \(b = 1\), so distant neighbours get weights near 0.01 and barely move the fit.

6.4.2 · slides 407–411

When to use nearest neighbours

k-NN suits low-dimensional data with plenty of examples and complex local structure, trains instantly and loses no information. Its challenges are choosing \(k\) and the distance metric, slow and costly queries, and sensitivity to irrelevant features and scale.

6.1, 6.3.4 · slides 412–413

Model selection with a validation set

Model selection compares candidates to choose one; model assessment estimates the chosen model's generalisation error. Tuning on the test set and then reporting test error is optimistic, so hold out a validation (dev) set for tuning and touch the test set once.

6.5.1 · slides 417–421

Cross-validation

k-fold CV trains on \(k - 1\) folds and validates on the remaining one, rotating so every point is validated once; leave-one-out uses \(k = n\); stratified k-fold keeps class proportions in each fold. It uses data better than a single holdout split, at the cost of \(k\) fits per candidate.

6.5.2 · slides 422–424
M7 · Support Vector Machines · 12 items

Many separating hyperplanes

A linear classifier predicts \(f(x) = \operatorname{sign}(w^\top x + b)\). For linearly separable data infinitely many hyperplanes separate the classes, and a boundary that passes close to points misclassifies them after a small perturbation; the SVM's question is which one is best.

7.1.1 · slides 431–435

Margin and support vectors

The margin is the width the boundary could grow before hitting a data point; the maximum-margin classifier (linear SVM) picks the hyperplane with the widest one, which equals \(2/\lVert w \rVert\). The hyperplane is fixed entirely by the points on the margin, the support vectors; removing any other point leaves it unchanged.

7.1.2 · slides 436–438

Hard-margin primal problem

Maximising \(2/\lVert w \rVert\) is the same as minimising \(\tfrac{1}{2}\lVert w \rVert^2\) subject to \(y_i(w^\top x_i + b) \ge 1\) for every point. This is a quadratic objective with linear constraints, a convex QP with a unique optimum when the data are separable, and no solution when they are not.

7.2.1 · slides 438–443

Dual problem, Lagrange multipliers and KKT

Attaching a multiplier \(\alpha_i \ge 0\) to each constraint and setting the Lagrangian's derivatives to zero gives \(w = \sum \alpha_i y_i x_i\) and \(\sum \alpha_i y_i = 0\). Complementary slackness makes \(\alpha_i > 0\) only for support vectors, and the data appear in the dual only through inner products \(x_i^\top x_j\), which is what opens the door to kernels.

7.2.2 · slides 443–446, 464

The three-equation shortcut and its flaw

Erratum: the slide's worked example solves \(w \cdot x_i + b = y_i\) through three guessed support vectors as a plain linear system and gets \(\alpha_1 = -3.5\), \(\alpha_2 = \alpha_3 = 0.75\). This is not a valid dual solution: a multiplier is negative and \(\sum \alpha_i y_i = 5 \ne 0\). Always check \(\alpha_i \ge 0\), \(\sum \alpha_i y_i = 0\) and every margin constraint.

7.2.2 · slides 447–452

Soft margin and slack variables

Noisy or overlapping data have no separating hyperplane, so slack \(\xi_i \ge 0\) lets point \(i\) violate the margin at a cost \(C\xi_i\). \(\xi_i = 0\) is on or outside the correct margin, \(0 < \xi_i \le 1\) inside it but correctly classified, \(\xi_i > 1\) misclassified.

7.3.1 · slides 455–459

The C trade-off

Large \(C\) makes violations expensive: a narrow margin, few training errors, low bias and high variance (approaching the hard margin). Small \(C\) tolerates violations for a wide margin: more bias, less variance. \(C\) is a regularisation knob and must be tuned by cross-validation.

7.3.2 · slides 457, 459–463

Mapping to a feature space

Data that are not linearly separable in the input space can become separable after a mapping \(\Phi(x)\) to a higher-dimensional space: 1-D points with one class inside an interval separate after \(\Phi(x) = (x, x^2)\). The SVM then finds a linear boundary in that space, which is non-linear in the original one.

7.4.1 · slides 465–470

The kernel trick

Because the dual uses only inner products, replace \(x_i^\top x_j\) by a kernel \(K(x_i, x_j) = \Phi(x_i)^\top \Phi(x_j)\) and never build \(\Phi\) explicitly. A valid kernel must give a symmetric positive semi-definite Gram matrix; the trick saves feature-space cost, not the cost of comparing every pair of training points.

7.4.1 · slides 467, 476, 479

Common kernels

Linear \(x_i^\top x_j\); polynomial \((1 + x_i^\top x_j)^p\) (degree 1 is linear); Gaussian RBF \(\exp(-\lVert x_i - x_j \rVert^2 / 2\sigma^2)\), which corresponds to an infinite-dimensional space and gives very local, wiggly boundaries when \(\sigma\) is small; sigmoid \(\tanh(\beta_0 x_i^\top x_j + \beta_1)\).

7.4.2 · slides 468, 477–478

Multiclass SVM

An SVM is binary, so \(C\) classes (movie genres: action, drama, thriller) need one-vs-all (\(C\) classifiers, highest score wins) or one-vs-one (\(C(C - 1)/2\) classifiers, majority vote). For a kernel SVM whose training cost grows faster than linearly, OvO's many small problems are often cheaper.

7.5 · slide 481

SVM pros and cons

Pros: the kernel framework is flexible, the solution is a sparse set of support vectors (compact at test time), it works well even on small samples, and the convex QP has a global optimum. Cons: choosing the kernel and its parameters is tricky, and training needs kernel values for every pair of examples, so memory and time blow up on large problems.

7.5 · slide 482
M8 · Bayesian Learning · 17 items

Where cost functions come from

A distribution is a model plus a parameter \(\theta\); training a model means estimating \(\theta\) from data. Asking which \(\theta\) makes the observed data most probable explains both the least-squares cost (Gaussian noise) and the log-loss (Bernoulli labels), so each loss hides a distributional assumption.

8.1, 8.1.2, 8.1.3 · slides 487–491

The MLE recipe

For i.i.d. data write the likelihood \(L(\theta) = \prod f(x_i \mid \theta)\), take logs so the product becomes a sum, differentiate with respect to each parameter, set to zero and solve. With 3 heads in 10 tosses the MLE of \(p\) is 0.3, the observed proportion.

8.1.1 · slides 493, 501, 511–513

Least squares is the Gaussian-noise MLE

If \(y = \theta^\top x + \varepsilon\) with \(\varepsilon \sim N(0, \sigma^2)\), maximising the log-likelihood over \(\theta\) is exactly minimising the sum of squared errors. Change the noise model and the loss changes: Laplacian noise makes the MLE minimise mean absolute error, which is more robust to outliers.

8.1.2 · slides 494–498, 514–515

Logistic regression by MLE

With Bernoulli labels the log-likelihood is \(\sum [y_i \ln \sigma_i + (1 - y_i)\ln(1 - \sigma_i)]\), the negative of the cross-entropy. Its gradient equations are non-linear in \(\theta\) with no closed-form root, so it is maximised by gradient ascent; at \(\theta = 0\) every \(\sigma = 0.5\), and four points give \(LL = 4\ln 0.5 = -2.773\).

8.1.3 · slides 499–500, 516–517

MAP estimation

MAP picks the \(\theta\) with the highest posterior, likelihood times prior, so prior beliefs pull the estimate. With a uniform prior MAP equals MLE exactly, and as data accumulate the likelihood dominates and MAP tends to MLE. In the slide's example the posterior \(\propto 2x^2(1 - x)^2\) peaks at \(\hat{x}_{\text{MAP}} = 0.5\).

8.1.4 · slides 502–504, 509

Bayes' theorem

The posterior \(P(h \mid D)\) is the prior \(P(h)\) times the likelihood \(P(D \mid h)\), normalised by the evidence \(P(D)\). \(P(\text{class} \mid \text{evidence})\) is not \(P(\text{evidence} \mid \text{class})\): with a fraud prior of 0.002, detection rate 0.95 and false-alarm rate 0.03, an alert raises the fraud probability only to about 0.06.

8.2.1 · slides 492, 504

MLE, MAP and the coin factory

With three coin types, \(h_{\text{MLE}} = h_3\) (\(p = 0.8\)) explains the data best, but only 20% of coins are that kind, so \(h_{\text{MAP}} = h_2\) (\(p = 0.4\), posterior 0.568): the prior outweighs the likelihood advantage. Under a uniform prior the two coincide.

8.1.4, 8.2.2 · slides 518–519

Bayes optimal classifier

Rather than trust \(h_{\text{MAP}}\) alone, the Bayes optimal classifier weights every hypothesis's prediction by its posterior; no method using the same hypotheses and prior does better on average. With posteriors 0.4, 0.3, 0.3 where \(h_1\) says + and \(h_2, h_3\) say −, \(h_{\text{MAP}}\) predicts + but the optimal vote is − (0.6 against 0.4). In the coin example MAP predicts tails, Bayes optimal heads (\(P(H \mid D) \approx 0.536\)).

8.2.2 · slides 505–507, 519

Gibbs classifier

The Bayes optimal vote is expensive with many hypotheses, so Gibbs draws one hypothesis at random from the posterior and uses it alone. Surprisingly, its expected error is at most twice the Bayes optimal error.

8.2.3 · slide 508

Conditional independence and why Naïve Bayes needs it

The full class-conditional joint \(P(X_1, \dots, X_n \mid Y)\) over \(n\) binary features needs about \(2^{n+1}\) parameters, far too many to estimate (digit recognition from pixels). Assuming the features are independent given the class makes it a product of \(n\) one-feature terms, so the count grows only linearly.

8.3.1 · slides 521–527

Generative versus discriminative models

Generative models (Gaussians, Naïve Bayes, mixture models) learn \(P(X \mid Y)\) and \(P(Y)\), so they can sample synthetic data, and get \(P(Y \mid X)\) by Bayes' theorem. Discriminative models such as logistic regression learn \(P(Y \mid X)\) directly.

8.3.1, 8.4 · slides 521–522, 566

Discrete Naïve Bayes by counting

Estimate the class priors and each \(P(X_i = v \mid Y)\) as relative frequencies from the training table, multiply the prior by the likelihood of each observed attribute value, and predict the class with the largest score. The independence assumption is often violated, yet the \(\arg\max\) is often still right.

8.3.2 · slides 528–531

Zero-frequency problem and smoothing

One attribute value never seen with a class makes that class's whole product 0. In the churn example both classes score 0 unsmoothed; Laplace smoothing \((N_{vc} + 1)/(N_c + d)\) gives Yes \(0.0343\) against No \(0.0181\), so predict churn with \(P(\text{Yes} \mid x) \approx 0.654\). The m-estimate generalises this with a prior \(p\) worth \(m\) virtual examples.

8.3.3 · slides 532–539

Gaussian Naïve Bayes

For a continuous feature, fit one Gaussian \(N(\mu_{ik}, \sigma_{ik}^2)\) per (feature, class) pair and use its density as the likelihood. A density is not a probability and can be tiny or above 1: at Humidity = 60 the Yes density \(N(60; 84.33, 1.33)\) is \(1.28 \times 10^{-97}\) against 0.0179 for No, which settles the vote.

8.3.4 · slides 540–549

Text classification: bag of words, multinomial and Bernoulli

The bag-of-words representation keeps word counts and ignores order. Multinomial NB models counts (repeated words count repeatedly, absent words contribute nothing); Bernoulli NB models presence or absence of every vocabulary word, so absent words count too and repetitions do not. On the Stanford "China" example multinomial NB assigns \(d_5\) to China (0.0003 > 0.0001) while Bernoulli NB does not (0.005 < 0.022).

8.3.5 · slides 550–565

Gaussian NB reduces to the logistic form

If \(Y \sim \text{Bernoulli}(\pi)\), each \(X_i \mid Y\) is Gaussian with a variance that does not depend on the class, and the \(X_i\) are conditionally independent, then \(P(Y = 1 \mid X)\) is exactly a sigmoid of a linear function. Logistic regression fits that form directly, so it is more robust when the Gaussian assumptions fail, while GNB converges faster on little data.

8.4 · slides 567, 571–574

Features and practical issues of Bayesian learning

Each training example nudges a hypothesis's probability up or down instead of eliminating it outright, and prior knowledge combines naturally with data. The costs: many initial probabilities must be supplied or estimated, and the Bayes optimal hypothesis is expensive in general (linear in the number of hypotheses).

8.2.1 · slides 568–569
M9 · Ensemble Learning · 10 items

Weak learners into a strong learner

A weak learner is only slightly better than random guessing; combining many of them can give a strong learner. If 3 independent classifiers are each right with probability 0.7, a majority vote is right with probability 0.784, and 5 give 0.837. The gain depends on diversity: correlated learners make the same mistakes, and learners worse than 0.5 make voting worse. Homogeneous ensembles combine copies of one algorithm trained on different data or weights (bagging, random forests, boosting); heterogeneous ensembles combine different algorithms (stacking).

9.1.1 · slides 582–587

Matching the ensemble to the base learner

Bagging trains learners in parallel and averages them, which reduces variance, so it suits low-bias, high-variance learners such as deep trees. Boosting trains them sequentially on re-weighted data, which reduces bias, so it suits high-bias, low-variance learners such as stumps. Stacking blends heterogeneous models with a meta-model.

9.1.2 · slides 582–587, 605

Bootstrapping

A bootstrap sample draws \(n\) records with replacement from \(n\): some records repeat and about \(1 - e^{-1} \approx 63.2\%\) of the distinct records appear. The remaining 36.8% are that sample's out-of-bag records, a free validation set.

9.2.1 · slides 589–596

Bagging

Bootstrap aggregating trains one model per bootstrap sample, in parallel, and aggregates by averaging (regression) or majority vote (classification). It cannot fix a learner that is biased, because averaging biased models stays biased.

9.2.1 · slides 597–602

Random Forest

A random forest bags decision trees and, at every split, considers only a random subset of features (typically \(\sqrt{p}\) for classification). This decorrelates the trees, so averaging removes more variance than plain bagging. The slides' examples are majority votes: trees saying Pass, Fail, Pass give Pass.

9.2.2 · slides 603, 611–614

Sequential reweighting in boosting

Boosting trains learners one after another, each focusing on the previous ones' mistakes by giving misclassified records more weight (AdaBoost) or by fitting the remaining errors (gradient boosting). The final model is a weighted combination of all learners.

9.3.1 · slides 605, 618–622, 641

AdaBoost mechanics

Start with equal weights (\(1/6\) each for the six churn customers), fit a stump, compute its weighted error \(\varepsilon\) and its say \(\alpha = \tfrac{1}{2}\ln\frac{1 - \varepsilon}{\varepsilon}\), raise the weights of misclassified records and lower the rest, renormalise, and repeat; predict \(\operatorname{sign}(\sum \alpha_t h_t(x))\). A stump with \(\varepsilon = 0.5\) gets \(\alpha = 0\). Keep exact values: with \(\varepsilon = 2/7\), \(\alpha = \tfrac{1}{2}\ln 2.5 \approx 0.458\), while rounding \(\varepsilon\) to 0.28 first gives 0.472.

9.3.2 · slides 618–629

Gradient boosting

Start from a constant prediction (the mean for regression), fit a small tree to the residuals, add it scaled by a learning rate, recompute the residuals and repeat. For squared loss the residual is the negative gradient, so each tree is one step of gradient descent in function space; a small learning rate needs more trees but generalises better.

9.3.3 · slides 615–616, 631–637, 641

What makes XGBoost "extreme"

XGBoost is regularised gradient boosting: a complexity penalty on leaves and leaf values in the objective, shrinkage (the slides' example uses \(\eta = 0.3\) from a base of 25 and predicts 19.9 at \(X = 3\), 30.1 at \(X = 7\)), depth-wise growth followed by pruning of splits that do not improve the objective, sparsity-aware default directions for missing values, and cache-aware, parallel computation for speed.

9.3.4 · slides 630–643

Stacking

Stacking trains heterogeneous base learners (e.g. logistic regression, random forest, k-NN) and a meta-model that learns how to combine their predictions. The meta-model must be trained on out-of-fold predictions, or it learns to trust whichever base model overfits most.

9.4 · slides 644–648
M10 · Unsupervised Learning · 13 items

The clustering goal

Group objects so that points in a cluster are close (small intra-cluster distance, cohesion) and clusters are far apart (large inter-cluster distance, separation). Uses include understanding (related documents, genes, stocks) and summarisation; dividing students alphabetically or grouping by a query is not cluster analysis, because the groups come from an external rule.

10.1.1 · slides 654, 702–703

Partitional versus hierarchical clustering

Partitional clustering divides the data into non-overlapping subsets, each point in exactly one (K-means, K-medoids); hierarchical clustering builds a set of nested clusters organised as a tree (dendrogram) that can be cut at any level.

10.1.2 · slide 704

K-means as alternating E- and M-steps

Pick \(K\) initial centroids, then alternate: assign each point to its nearest centroid (E-step, fixing \(\mu_k\) to choose \(r_{nk}\)), and recompute each centroid as the mean of its points (M-step, fixing \(r_{nk}\) to choose \(\mu_k\)). For A(1,2), B(1,4), C(1,0), D(10,2), E(10,4), F(10,0) with initial centroids A and D, the clusters {A, B, C} and {D, E, F} already have means (1, 2) and (10, 2), so it stops after one pass.

10.2.1 · slides 655–662, 705–706

K-means objective and convergence

K-means minimises \(J = \sum_n \sum_k r_{nk}\lVert x_n - \mu_k \rVert^2\), the SSE. Each E-step and each M-step can only lower or keep \(J\), and there are finitely many assignments, so it always converges, but only to a local minimum that depends on the initial centroids; run several initialisations and keep the lowest SSE.

10.2.2 · slides 655, 660, 663

Choosing K with the elbow method

Compute SSE for \(K = 2, 3, 4, \dots\) and plot it; SSE always falls as \(K\) grows (to 0 at \(K = N\)), so choose the bend where extra clusters stop paying. With no clear elbow, use the silhouette as well.

10.2.3 · slide 670

Limitations of K-means

K-means struggles when clusters differ in size or density or are non-globular (elongated, nested), because it favours round clusters of similar spread. It is also pulled by outliers, since one extreme value moves a mean a long way. A point's distance to its centroid over the cluster's average distance gives a naive outlier score (higher means more likely an outlier).

10.2.4 · slides 665–668, 671, 708–709

K-medoids

K-medoids uses a medoid, the actual data point with the smallest total dissimilarity to the rest of its cluster, instead of the mean, so outliers cannot drag the centre off the data. Starting from medoids A(1,1) and D(8,1), the slides' example settles on medoids B(2,3) and E(9,3). For \((1,1), (2,1), (1,2), (2,3), (9,8)\) the centroid is pulled to \((3, 3)\), while the medoid stays among the four close points.

10.3 · slides 669, 711–715

Internal, external and relative validity indices

An internal index (SSE, cohesion, separation) judges a clustering from the data alone; an external index (entropy, purity) compares cluster labels with known class labels; a relative index compares two clusterings or values of \(K\). Any index needs a framework (how atypical is this value?) to be interpreted.

10.4.1 · slides 716–721

Silhouette coefficient

For each point, \(a\) is its average distance to its own cluster and \(b\) the smallest average distance to another cluster; \(s = 1 - a/b\) when \(a < b\). Values near 1 mean well placed, near 0 on a border, negative probably misassigned; averaging over points gives a score for a cluster or a whole clustering.

10.4.2 · slide 722

Hard versus soft clustering

K-means makes hard assignments, each point to exactly one cluster via the 1-of-K indicators \(r_{nk}\), which is awkward for overlapping or non-circular clusters. A Gaussian mixture model gives soft, probabilistic assignments that express uncertainty.

10.5.1 · slides 672–675

Gaussian mixture density

A single Gaussian is unimodal, so multimodal data are modelled as a weighted sum of \(K\) Gaussians, \(p(x) = \sum_k \pi_k \mathcal{N}(x \mid \mu_k, \Sigma_k)\), with mixing weights \(\pi_k\) that sum to 1 and act as priors on which component generated a point.

10.5.2 · slides 676–688, 723–726

EM for GMMs

The E-step computes each point's responsibilities \(\gamma(z_{nk})\) by Bayes' theorem with the \(\pi_k\) as priors; the M-step re-estimates \(\pi_k, \mu_k, \Sigma_k\) by responsibility-weighted MLE, with \(N_k = \sum_n \gamma(z_{nk})\) as the effective cluster size. Repeat until the log-likelihood stops increasing. Erratum: in the document example the second responsibility, 0.994, belongs to Cluster 2, not Cluster 1 (the two sum to 1 with 0.006).

10.5.3 · slides 689–699

Covariance options and practical issues

"spherical" clusters are round with their own variance, "diag" are axis-aligned ellipses, "tied" share one covariance, "full" can be any ellipse. EM needs \(K\) chosen in advance, finds only local optima that depend on initialisation (sklearn's n_init), and can hit singularities when a component collapses onto one point.

M11 · ML Model Evaluation, Comparison & FAccT ML · 8 items

The evaluation workflow

Train on the training set, tune hyper-parameters on validation data or by cross-validation (holdout, k-fold, leave-one-out, stratified k-fold, bootstrap), and evaluate the final model once on unseen test data. Using the test set for tuning silently inflates the reported score.

11.1.1 · slides 730–733

Classification and regression metrics side by side

For classification use accuracy, precision, recall, F1 and ROC-AUC, preferring the rare-class metrics under imbalance. For regression use MSE/RMSE (punish large errors), MAD/MAE (linear in error), MAPE (scale-free, undefined at zero) and \(R^2\) (against predicting the mean). Different metrics can rank the same models differently, so choose the one that matches the real cost.

11.1.2 · slide 733

Is one model really better?

Comparing models is two steps: put a confidence interval on each model's accuracy, then test whether the observed gap is statistically significant. Test accuracy is a sample proportion with standard error \(\sqrt{p(1 - p)/n}\), so 0.85 on 1000 cases gives a 95% interval of about \([0.828, 0.872]\); a small gap on a small test set is often just noise.

11.2.1 · slide 734

FAccT: the emerging requirements

Beyond accuracy, deployed models must be fair (no gender or ethnic discrimination), accountable (someone answers for failures), transparent (understandable and compliant with regulation), private and robust. The field draws on statistics, ML, social science, psychology and public policy.

11.3.1 · slides 735–737

Algorithmic bias and negative legacy

ML models approximate the patterns in their data, so they learn and can amplify its biases. COMPAS, a commercial tool that scored over a million offenders on 137 features for reoffending risk, became the standard example. When historical labels themselves reflect past discrimination (negative legacy), every model and metric trained against them inherits it.

11.3.1 · slides 738–740

Why fairness through unawareness fails

Dropping the sensitive attribute (race, ethnicity) does not make a model fair, because other features can act as proxies that redundantly encode it: in the slides' hiring example, "often goes to Mexican markets" stands in for ethnicity. Fairness must be measured on outcomes per group, not assumed from the inputs.

11.3.2 · slides 741–742

Interpretable models versus black boxes

Decision trees (read the rule path), linear and logistic regression (read signed coefficients or odds ratios) and k-NN (read the neighbours) explain their own decisions. Ensembles and deep nets are black boxes that need post-hoc explanation, which matters for end users' trust, for debugging and for regulators.

11.4.1 · slides 743–747

The interpretability–performance trade-off

High-performing models tend to be less interpretable (on MNIST, deep networks beat the readable models). Whether a black box is acceptable depends on the stakes: a loan or parole decision needs explanations, a movie recommender less so.

2.3 The most common misconceptions (targeted by L1 and L5 problems)

Misconception Reality Targeted in
"A classifier with 99% accuracy is obviously good." Not under class imbalance — predicting the majority class every time can reach 99% accuracy while missing every rare case (fraud, disease, defect). M4
"Tuning hyper-parameters on the test set is fine, as long as I don't retrain on it." It still leaks information: the reported generalisation error becomes optimistic because the model/hyper-parameters were selected to do well on that exact set. The slides state this directly: "the test data can't be used for parameter tuning." M2, M6, M11
"A decision tree that gets 100% training accuracy is the best tree." It is very likely overfit: a perfectly pure tree has memorised noise. Pre-/post-pruning trade a little training accuracy for better test accuracy. M5
"Larger \(k\) in k-NN is always safer." \(k\) trades bias and variance: \(k = 1\) overfits to noise (high variance); \(k \to N\) underfits to the global majority class (high bias). The elbow method exists precisely to find the middle. M6
"More regularisation can only help." Too much regularisation underfits (high bias); the strength must be tuned, typically via validation/cross-validation, like every other hyper-parameter. M3, M4
"Bagging and boosting do the same thing, just with different names." Bagging trains independent learners in parallel to reduce variance (good with high-variance, low-bias base learners such as deep trees). Boosting trains learners sequentially, re-weighting mistakes, to reduce bias (good with high-bias, low-variance base learners such as shallow stumps). M9
"Naïve Bayes's conditional-independence assumption is harmless in practice." It is frequently violated (e.g. Plan and Usage are correlated given churn in the slides' own telecom example) yet the classifier often still ranks the classes correctly, because only the \(\arg\max\) over classes needs to be right, not the exact probabilities. M8
"A Gaussian Mixture Model assigns every point to one cluster, like k-means." GMM gives soft responsibilities \(\gamma(z_{nk})\) that sum to 1 across clusters for each point; a hard assignment (if needed) is a separate, later decision. M10
"\(P(\text{class} \mid \text{evidence}) = P(\text{evidence} \mid \text{class})\)." They differ unless the prior and evidence probabilities happen to coincide; conflating them is the same base-rate error that breaks medical-test and spam-filter reasoning if not corrected by Bayes' theorem. M8
"A Lagrange multiplier \(\alpha_i\) in an SVM can be negative, or the set of multipliers found by any system of equations through the support vectors is automatically a valid solution." A genuine dual solution requires every \(\alpha_i \ge 0\) and \(\sum \alpha_i y_i = 0\); a system of equations that merely forces the margin to pass exactly through the chosen support vectors can produce a negative \(\alpha_i\), which is not a valid Lagrange multiplier (see errata item 1 below). M7
"Feature scaling is a formality; gradient descent converges to the same place either way." It converges to the same minimiser, but the path and the number of iterations differ enormously: unscaled features give elongated, skewed cost contours and a zig-zagging, slow descent. M3

2.4 Errata and ambiguities spotted in the slides (do not copy these into exams)

  1. Module 7 (SVM), Session 10, "Numerical Example" (the three-support-vector hyperplane problem): solving the three linear equations through the support vectors \(S_1 = (1, 0, y = -1)\), \(S_2 = (3, 1, y = +1)\), \(S_3 = (3, -1, y = +1)\) gives \(\alpha_1 = -3.5\), \(\alpha_2 = 0.75\), \(\alpha_3 = 0.75\). This is not a valid dual solution: every Lagrange multiplier must satisfy \(\alpha_i \ge 0\), and the KKT stationarity condition requires \(\sum \alpha_i y_i = 0\), but here \(\sum \alpha_i y_i = (-3.5)(-1) + 0.75(1) + 0.75(1) =\) \(5.0 \ne 0\). The slide's shortcut (solve "\(w \cdot x_i + b = y_i\)" through the three support vectors as a plain \(3 \times 3\) linear system) skips the dual's own constraints and should not be used as a template for solving a general SVM dual by hand.
  2. Module 3, Session 3&4, "Numerical Exercise" + its "Answer" slide (regularisation with gradient descent): after one ridge-regression update the weights shrink slightly (as expected — ridge's multiplicative shrink factor \((1 - \eta \cdot \lambda)\) is applied), but the slide's own Lasso answer (\(w_1 = 0.1477\), \(w_2 = 0.2793\)) comes out larger than both the unregularised weights (0.0477, 0.1793) and the ridge weights (0.0507, 0.1823), directly contradicting the slide's own interpretation line "Lasso Adds fixed penalty → can push weights toward zero faster." The slide never actually states the correct L1 subgradient update (\(w \leftarrow w(1 \text{ at non-zero}) - \eta \cdot \nabla \text{MSE} - \eta \cdot \lambda \cdot \operatorname{sign}(w)\)); treat the given Lasso numbers as unreliable.
  3. Module 10, Session 14, GMM worked example ("VI Maximization Step" page, the document-membership calculation): the responsibility of document 1 to the second cluster is printed with the same label as the first — "\(P(Z_{\text{Doc1‑Cluster1}}) = 0.006\)" followed immediately by "\(P(Z_{\text{Doc1‑Cluster1}}) = 0.994\)" — the second line should read \(P(Z_{\text{Doc1‑Cluster2}}) = 0.994\) (the two responsibilities for a point must sum to 1, which \(0.006 + 0.994\) does, confirming the value is right and only the cluster label is wrong).
  4. Module 2, Session 2, IQR outlier worked example (page 96, data 10,11,11,11,12,12,13,14,14,15,17,22): \(Q_1 = 11\) and \(Q_3 = 14.5\) are obtained by the median-of-halves method (median of the lower six values, median of the upper six values), not by the position formula \(k(n+1)/4\) used elsewhere in the slides (which would give \(Q_1 = 11\), \(Q_3 = 14.75\) — close but not identical). Both conventions are legitimate; state which one you are using in an answer, exactly as for the ISM course's quartile ambiguity.
  5. Module 9, AdaBoost worked numeric example: the total error is \(\varepsilon = 2/7\), which is often rounded to 0.28 on the way. With the exact value the ratio \((1 - \varepsilon)/\varepsilon\) is exactly 2.5 and the stump performance is \(\alpha = \tfrac{1}{2}\ln 2.5 \approx \mathbf{0.458}\). Rounding \(\varepsilon\) to 0.28 first turns the ratio into \(0.72/0.28 \approx 2.571\) and \(\alpha\) into \(\approx 0.472\), which is a visible change in the third digit. The lesson is general: carry exact fractions (or at least four significant figures) through intermediate steps and round only the final answer.

2.5 How the problem bank is designed

  • Every leaf of the tree is hit by at least one problem. Bottleneck nodes (gradient descent mechanics, hand-computed scores, Bayes' direction, train/validation/test discipline) are hit several times at increasing levels across different modules.
  • L1 problems check vocabulary and catch misconceptions before computation starts.
  • L2 problems use small, clean numbers, so mechanics are separated from reading comprehension.
  • L3 problems mirror the style of the worked "Problem Type" exercises embedded in the slides themselves.
  • L4 problems make you derive results: why least squares is the MLE under Gaussian noise, why a Lagrange multiplier must be non-negative, why Lasso's gradient does not exist at 0, why Random Forest's feature subsampling decorrelates trees. Once you can derive a result, you no longer need to memorise it.
  • L5 problems connect a topic to real model-building judgement (choosing a metric under imbalance, diagnosing why a model overfits, picking an ensemble strategy for a given base learner) or set a deliberate misconception trap.
  • Each module ends with a module capstone that uses the whole module. Part 14 holds cross-module capstones that combine three or more modules, the way an actual ML project does.

Suggested study loop per topic: do all L1 \(\to\) all L2 \(\to\) L3 \(\to\) L4, checking each answer as you go, then attempt L5 without hints. Re-attempt anything you got wrong after 48 hours.
