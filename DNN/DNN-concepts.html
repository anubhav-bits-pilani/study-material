M1 · Introduction to Deep Learning · 12 items

Deep learning as layered feature extraction

Deep learning is machine learning with neural networks whose many stacked layers each transform the previous layer's output, so later layers represent progressively higher-level features (edges, then parts, then objects). The features are learned from data rather than hand-engineered, which is the practical difference from classical ML.

1.1.1 · slides 4, 7

AI, ML and DL, and what "depth" counts

AI is the broad goal of making machines perform human tasks (some of it involves no learning at all), ML is the subset that learns from experience, and DL is the subset of ML that uses multi-layer neural networks. The depth of a model is the number of layers that contribute to modelling the data.

1.1.2 · slides 5–7

The historical arc

McCulloch–Pitts neuron (1943), Rosenblatt's perceptron (1958), Minsky and Papert's XOR critique (1969), backpropagation popularised (1986), LeNet-5 (1998), AlexNet on GPUs (2012), the Transformer (2017), BERT and GPT (2018). Each milestone fixes a limitation of the previous one, which is also the order of this course.

1.1.3 · slides 11, 13–18

Why deep learning took off now

The ideas are old; what changed is scale. Huge amounts of unstructured data (images, text, audio, video), cheap sensors, cheap compute (GPUs, distributed clusters) and cheap storage made it possible to train large networks that learn their own features.

1.2.1 · slide 9

Scale drives progress (performance vs data)

On Andrew Ng's curve, traditional ML (logistic regression, SVM) plateaus as labelled data grows, while small, medium and large networks keep improving, the large one most. With small training sets the ordering is unclear and hand-engineered features can win; the advantage of big networks appears only with lots of data.

1.2.2 · slide 10

Matching the network family to the input

The deck's table maps tasks to families: tabular data such as house features to price uses a standard NN; images (photo tagging, object detection) use a CNN; sequences (speech to text, English to French) use an RNN; mixed sensor inputs (autonomous driving) use a hybrid network. The structure of the input, not the task name, decides the family.

1.3 · slides 19–20

The four components of every DL problem

Every problem is data (\(D = \{X, t\}\) with \(N\) examples and \(d\) features), a model (a chain of transformations), an objective function (by convention lower is better, hence "loss") and a learning algorithm (usually gradient descent) that searches for the parameters minimising the loss. Every later architecture changes only the model column of this recipe.

1.4.1, 1.4.2, 1.4.3, 1.4.4 · slides 22–27

Counting examples and features

In the deck's house table each row is an example and each column used for prediction is a feature, so adding houses increases \(N\) and adding attributes increases \(d\) (the dimensionality). The ID column is neither a feature nor the target, and a categorical column such as Location must first be converted to numbers.

1.4.1 · slides 23–24

A loss must give a usable gradient

Gradient descent moves parameters against the gradient of the loss, so the loss must be differentiable with informative slopes. "Number of mistakes" is piecewise constant, so its gradient is zero almost everywhere; smooth surrogates such as MSE and cross-entropy are used instead.

1.4.3, 1.4.4 · slides 26–27

Model family vs trained model vs parameters

A model family is the set of all input-output mappings obtainable by changing the parameters; training picks one member by fixing the parameters, and only then is it "a model". The deck's example: the same family suits "Alexa" and "Hey Siri" wake-word detection, with different trained parameters.

1.4.5 · slides 28–30

Supervised learning tasks

Supervised learning fits a map from features to labels using labelled examples. Regression answers "how much or how many"; classification is binary, multi-class or multi-label (several labels at once); recommender systems and sequence learning (tagging, speech recognition, text to speech, translation) are also supervised.

1.5.1 · slides 32–34

Unsupervised and reinforcement learning

Unsupervised learning gets only features, no labels, and looks for structure: clustering, density estimation, or generating synthetic data with GANs. Reinforcement learning has an agent take actions in an environment over time steps and learn from rewards; the course only names it.

M2 · Artificial Neural Network · 17 items

The biological neuron

Dendrites receive signals from other neurons, the soma (cell body) combines them, the axon carries the output signal, and synapses are the connection points whose strengths adapt. The artificial neuron copies exactly this pipeline: inputs, weighted combination, output, adjustable connection strengths.

2.1.1 · slide 43

Brain-scale numbers and parallelism

The brain has about \(10^{10}\) neurons with \(10^4\)–\(10^5\) connections each, and a neuron switches in about 0.001 s. Recognising a scene in 1 s leaves only about 1000 serial steps (the slide's "100 steps" corresponds to 0.1 s), so the brain must compute massively in parallel, which is the inspiration for parallel, distributed networks.

2.1.2 · slides 41–42

The artificial neuron

A neuron computes a weighted sum \(z = \sum_i w_i x_i + b\) and passes it through an activation, \(\hat{y} = f(z)\). Each weight says how important its feature is, the bias shifts the threshold, and the choice of \(f\) (step, sigmoid, identity, ReLU) decides what kind of output the neuron produces.

2.1.3 · slides 45–47

What the artificial neuron keeps and discards

The biological neuron is analog, biochemical, adaptive and fault tolerant; the artificial one is a simple, deterministic, digital formula with adjustable weights learned by an algorithm. It keeps only the essential computation (weighted inputs, a nonlinearity, learnable connection strengths).

2.1.4 · slide 48

Artificial neural networks and their connections

An ANN is many interconnected neurons arranged in input, hidden and output layers, with connections that may be forward, recursive (back to earlier layers) or self-loops. It is highly parallel and distributed, and its weights are tuned automatically from data, which lets it approximate complex functions.

2.2.1 · slides 50–51

When an ANN is the right tool

Prefer an ANN when the input is high-dimensional (raw sensor data, pixels), the data may be noisy, the form of the target function is unknown, and explainability does not matter; speech recognition, image classification and financial prediction are the deck's examples. When a readable rule is legally or practically required, a neural network is a poor choice.

2.2.2 · slide 52

Connectionism: knowledge lives in the weights

Connectionist machines store all their knowledge in the connection weights between simple units, and learning means changing those weights. Intelligence emerges from many simple units working in parallel, not from any single clever unit.

2.2.3 · slides 54–55

The perceptron as a threshold unit

Rosenblatt's perceptron (1958) is a single neuron with a step activation: \(\hat{y} = +1\) if \(\sum_i w_i x_i + b \ge 0\), else \(-1\). Its decision boundary \(w^\top x + b = 0\) is a hyperplane, so it is a linear classifier, and since a step depends only on the sign of \(z\), only the direction of \((w, b)\) matters, not its length.

2.3.1 · slides 57–58

Hand-designing logic gates

To build a gate, write one inequality per truth-table row and find any \((w_0, w_1, w_2)\) satisfying all four. The deck finds AND with \(w_0 = -1\), \(w_1 = w_2 = 0.75\) and OR with \(w_0 = -1\), \(w_1 = w_2 = 2\); negating all three weights turns these into NAND and NOR (valid here because no row lands exactly on \(h = 0\)), and NOT is \(w_1 = -1\), \(w_0 = 0\). Infinitely many solutions exist.

2.3.2 · slides 60–66

Output conventions: {0, 1} vs {−1, +1}

Rosenblatt's perceptron outputs \(\{-1, +1\}\), while the deck's gate examples use \(\{0, 1\}\). Both are valid, but the bias you solve for and the size of each update differ (an error is \(t - \hat{y} = \pm 1\) in one case, \(\pm 2\) in the other), so state the convention before solving a gate problem.

2.3.3 · slide 60

The perceptron learning rule

For each example, predict; if \(\hat{y} \ne t\) update \(w_i \leftarrow w_i + \eta(t - \hat{y})x_i\) and \(b \leftarrow b + \eta(t - \hat{y})\); repeat until a full epoch has no errors. Correct predictions change nothing, and a wrong one moves the boundary toward classifying that example correctly.

2.4.1 · slide 68

Hand-simulating epochs (NOT gate)

From \(w_0 = w_1 = 0\) and \(\eta = 1\), the NOT gate errs on \(x_1 = 1\) in epoch 1 (giving \(w_1 = -1\), \(w_0 = -1\)), errs on \(x_1 = 0\) in epoch 2 (giving \(w_0 = 0\)), and epoch 3 is error-free, so it converges to \(w_1 = -1\), \(w_0 = 0\). Keep a table of \(h\), \(\hat{y}\), \(t\) and the weights after each example.

2.4.2 · slides 69–74

The learning rate and the zero start

Starting from zero weights, any \(\eta > 0\) gives exactly the same predictions and number of updates as \(\eta = 1\), with all weights scaled by \(\eta\), because \(\operatorname{step}(\eta z) = \operatorname{step}(z)\). Only against a non-zero initialisation does \(\eta\) change how many updates are needed.

2.4.1, 2.4.3 · slide 68

Perceptron convergence theorem

If the data are linearly separable, the perceptron rule reaches a separating hyperplane in a finite number of updates (at most \((R/\gamma)^2\) mistakes, with \(R\) the largest input norm and \(\gamma\) the margin). If the data are not separable, as with XOR, it never converges and cycles forever.

2.4.3 · slide 68

Linear separability

Two classes are linearly separable in \(n\) dimensions if an \((n-1)\)-dimensional hyperplane separates them: a line in 2-D, a plane in 3-D. Augmenting \(\tilde{x} = (1, x_1, \dots, x_n)\) folds the bias in as \(w_0\), so the perceptron is \(h = w^\top \tilde{x}\) with \(n + 1\) parameters; if one separator exists, infinitely many do.

2.5.2 · slides 80–83

XOR breaks the single perceptron

XOR is 1 on \((0,1)\) and \((1,0)\) and 0 on \((0,0)\) and \((1,1)\). Adding the inequalities for the two positive points gives \(w_1 + w_2 + 2b \ge 0\), while the two negative points give \(w_1 + w_2 + 2b < 0\), a contradiction, so no line separates the classes and a single perceptron cannot learn XOR.

2.5.1 · slides 76–77

Hidden layers solve XOR

Two hidden perceptrons computing OR and NAND, fed into an AND output, compute XOR: the hidden layer remaps the four points into a space where they are linearly separable. The nonlinearity of the hidden units is essential, because stacked linear layers collapse into one linear layer; this is the bridge to multilayer networks in M5.

M3 · Linear Neural Networks for Regression · 15 items

Regression as a map to the real line

Regression is supervised learning of \(f : \mathbb{R}^d \to \mathbb{R}\) so that \(y \approx f(x)\) for a continuous target (house price, temperature, stock price). Linear regression assumes the output is a linear combination of the features, \(y = w_0 + w_1 x_1 + \dots + w_d x_d\).

3.1 · slides 91–96

Design matrix and vectorised prediction

Prepend a 1 to every example so the bias becomes \(w_0\); stacking the \(N\) augmented rows gives the design matrix \(X \in \mathbb{R}^{N \times (d+1)}\), with \(w \in \mathbb{R}^{d+1}\) and targets \(y \in \mathbb{R}^N\). All predictions are then one product, \(\hat{y} = Xw\), which is how the computation is done efficiently.

3.1 · slide 99

Linear regression is a single neuron

A single neuron with weights \(w\), bias \(w_0\) and identity activation \(f(z) = z\) computes exactly \(\hat{y} = w^\top x\). Seeing regression as the simplest network matters because every later model keeps this neuron and only changes the activation, the loss and the number of layers.

3.2.1 · slides 98, 100–101

Why identity activation for regression

The target is continuous and unbounded, so the output must be able to take any real value; the identity has range \((-\infty, \infty)\), derivative 1 everywhere, and passes the gradient through unchanged. A sigmoid or step would squash predictions into a bounded range and could never output a price of 350K.

3.2.2 · slides 102–103

Mean squared error

The per-example loss is the squared residual and the objective averages it, \(J(w) = \frac{1}{2N}\lVert Xw - y\rVert^2\). The slides use both \(1/N\) (slide 104) and \(1/(2N)\) (slide 105); they have the same minimiser, the \(\tfrac12\) only cancels the 2 from differentiating, so pick one and stay consistent.

3.3.1 · slides 104–105

Why squared error

Squared error is smooth and differentiable, convex for a linear model (one global minimum, a bowl-shaped error surface), penalises large errors quadratically, and is exactly the maximum-likelihood objective when the noise is Gaussian. The flip side of the quadratic penalty is sensitivity to outliers.

3.3.2 · slides 105–106

The gradient of the MSE

Differentiating gives \(\nabla J(w) = \frac{1}{N} X^\top (Xw - y)\): the error vector \(e = \hat{y} - y\) weighted by each feature and averaged. Shapes check it: \(X^\top\) is \((d+1) \times N\) and \(e\) is \(N \times 1\), so the gradient has one entry per weight.

3.4.1 · slide 109

Batch gradient descent and the learning rate

Each step uses all \(N\) examples, \(w \leftarrow w - \eta \nabla J(w)\), and moves perpendicular to the loss contours toward the minimum. Too large an \(\eta\) overshoots, oscillates or diverges to NaN; too small converges slowly; stop when \(\lVert \nabla J \rVert < \epsilon\) or after a maximum number of iterations.

3.4.2 · slides 107–111

Hand-worked GD step

For sizes \(x = (1, 2, 3)\), prices \(y = (2, 4, 5)\), \(w^{(0)} = 0\) and \(\eta = 0.1\): the initial loss is \(\frac{1}{6}(4 + 16 + 25) = 7.5\), the gradient is \(\frac{1}{3}(-11, -25) = (-3.67, -8.33)\), so \(w^{(1)} = (0.367, 0.833)\), the predictions become \((1.20, 2.03, 2.87)\) and the loss drops to about 1.51, an 80% reduction in one step.

3.4.3 · slides 113–117

Train/test split and generalisation

Weights are fitted on the training set (typically 90–99% of the data) and judged on a held-out test set (1–10%). The goal is low test error, because training error alone cannot reveal overfitting.

3.5 · slide 120

Regression metrics: MSE, RMSE, MAE

MSE averages squared errors (units squared, dominated by large errors), RMSE is its square root (back in the target's units), and MAE averages absolute errors (less sensitive to outliers). With one big outlier MSE and RMSE jump much more than MAE.

3.5 · slide 121

\(R^2\) and its range

\(R^2 = 1 - SS_{\text{res}}/SS_{\text{tot}}\) is the fraction of target variance the model explains: 1 is a perfect fit, 0 means no better than always predicting \(\bar{y}\), and it can be negative on a test set when the model is worse than the mean. The deck calls 0.7 to 0.9 a good fit.

3.5 · slide 122

Practical tips: learning rate, stopping, initialisation

Search \(\eta\) on a log grid \(\{0.001, 0.01, 0.1, 1\}\) and plot loss curves; stop on small gradient, small loss change, an iteration cap, or rising validation loss. Zero initialisation is fine for linear regression because the loss is convex and there is no symmetry to break; avoid large initial values.

3.6 · slides 126–127

Feature scaling

Features on very different scales (square feet vs bedrooms) make the loss surface an elongated valley, forcing a small \(\eta\) and slow zig-zag convergence. Min-max scaling to \([0, 1]\) or z-score standardisation \((x - \mu)/\sigma\) makes the contours rounder and speeds gradient descent.

3.6 · slide 127

Debugging a regression run

NaN or Inf loss means \(\eta\) is too large or features are unscaled; oscillating loss also means \(\eta\) too large; a flat loss means \(\eta\) too small or a gradient bug (a wrong sign, a plus instead of minus in the update). Low training but high test error is overfitting: regularise, get more data or simplify.

M4 · Linear Neural Networks for Classification · 19 items

Classification vs regression; three kinds

Classification predicts a discrete label instead of a continuous value. Binary has two classes (spam or not), multi-class has \(K > 2\) mutually exclusive classes (digits 0–9), and multi-label lets one example carry several labels at once (a film that is action and comedy), which needs independent sigmoids rather than one softmax.

4.1 · slides 137–139

Why not linear regression for classification

A linear model outputs any real number, so it can predict "probabilities" below 0 or above 1, and squared error on 0/1 labels is distorted by points far from the boundary. The fix is to squash the linear score into \((0, 1)\) with a sigmoid and threshold at 0.5.

4.2.1 · slides 141–143

The sigmoid and its derivative

\(\sigma(z) = 1/(1 + e^{-z})\) maps \(\mathbb{R}\) to the open interval \((0, 1)\) (the slides' \([0, 1]\) is loose: it never reaches 0 or 1), with \(\sigma(0) = 0.5\) and \(\sigma(-z) = 1 - \sigma(z)\). Its derivative \(\sigma'(z) = \sigma(z)(1 - \sigma(z))\) peaks at 0.25 at \(z = 0\) and vanishes for large \(\lvert z \rvert\), the root of later vanishing-gradient trouble.

4.2.2 · slides 146–147

Logistic regression and its decision boundary

Logistic regression is one neuron with a sigmoid: \(z = w^\top x\) is the logit and \(\hat{y} = \sigma(z) = P(y = 1 \mid x)\). Predicting class 1 when \(\hat{y} \ge 0.5\) is the same as \(w^\top x \ge 0\), so the decision boundary \(w^\top x = 0\) is a hyperplane and the model is still a linear classifier.

4.2.3 · slides 145, 151–153

Binary cross-entropy

The loss is \(-\log \hat{y}\) when \(y = 1\) and \(-\log(1 - \hat{y})\) when \(y = 0\): small for confident correct predictions and growing without bound for confident wrong ones. It is the negative log-likelihood of a Bernoulli model, convex for logistic regression, and its raw derivative is \((\hat{y} - y)/[\hat{y}(1 - \hat{y})]\).

4.2.4 · slides 154–156

The sigmoid + BCE gradient collapses to \((\hat{y} - y)x\)

Multiplying \(\partial \ell / \partial \hat{y} = (\hat{y} - y)/[\hat{y}(1 - \hat{y})]\) by \(\sigma'(z) = \hat{y}(1 - \hat{y})\) cancels the denominator, leaving \(\partial \ell / \partial w = (\hat{y} - y)x\), the same form as linear regression. With MSE instead, an extra \(\hat{y}(1 - \hat{y})\) factor remains, so a confidently wrong neuron learns almost nothing.

4.2.5 · slides 157–159

Stochastic gradient descent

SGD updates after every single shuffled example, \(w \leftarrow w - \eta(\hat{y} - y)x\), instead of after the whole dataset. Iterations are cheap and memory is tiny, online learning is possible and the noise helps escape sharp minima, but the path is noisy and more sensitive to \(\eta\); mini-batch SGD is the usual compromise.

4.2.5 · slides 157–162

Hand-worked SGD trace (pass/fail by hours)

Hours \(1, 2, 3, 4\) with labels \(0, 0, 1, 1\), \(w^{(0)} = 0\), \(\eta = 0.5\): every first prediction is \(\sigma(0) = 0.5\). Example 1 (\(x = 1\), \(y = 0\)) gives gradient \(0.5 \cdot (1, 1)\) and \(w = (-0.25, -0.25)\); example 3 (\(x = 3\), \(y = 1\)) gives \(z = -1\), \(\hat{y} = 0.269\), error \(-0.731\) and \(w = (0.116, 0.847)\), after which predictions for the class-1 points move toward 1.

4.2.6 · slides 164–168

Confusion matrix and its four cells

Rows are the actual class, columns the predicted one: TP and TN are correct, an FP is a false alarm (Type I error) and an FN is a miss (Type II error). Every binary metric is a ratio of these four counts.

4.2.7 · slide 172

Accuracy, precision, recall, F1 and when to use each

Accuracy is misleading on imbalanced data (always predicting "negative" scores 95% when 95% are negative). Use precision when false positives are costly (spam filtering), recall when false negatives are costly (disease screening), and F1, their harmonic mean, when both matter; the deck's example with TP = TN = 3, FP = FN = 1 gives 0.75 for all four.

4.2.7 · slides 173–176

One-hot labels and the weight matrix

With \(K\) classes each label becomes a length-\(K\) one-hot vector, which imposes no false order on the classes and matches the shape of the softmax output. The model has one column of weights per class, \(W \in \mathbb{R}^{(d+1) \times K}\) with \((d+1)K\) parameters, and logits \(Z = XW\) for a whole batch.

4.3.1 · slides 185–189

Softmax and its properties

Softmax turns \(K\) logits into a probability vector: every output in \((0, 1)\), sum 1, order preserved, unchanged if a constant is added to every logit, and identical to a sigmoid of \(z_1 - z_2\) when \(K = 2\). For \(z = (2.0, 1.0, 0.1)\) it gives \((0.659, 0.242, 0.099)\): the exponential amplifies differences between logits.

4.3.2 · slides 190–192

Categorical cross-entropy and the \(\hat{y} - y\) gradient

CCE \(-\sum_k y_k \log \hat{y}_k\) depends only on the probability given to the true class: 0.8 costs 0.22, 0.2 costs 1.61, 0.05 costs 3.00. Combined with softmax the gradient with respect to the logits is simply \(\hat{y} - y\), and for \(K = 2\) CCE reduces to BCE.

4.3.3 · slides 194–196

Mini-batch SGD and batch size

Mini-batch SGD averages the gradient over \(B\) examples (\(1 < B \ll N\), typically 32–512), giving vectorised GPU-friendly computation with less noise than single-example SGD. An iteration is one update and an epoch one full pass, with \(\lceil N/B \rceil\) iterations per epoch: \(N = 60{,}000\), \(B = 128\) gives 469, so 10 epochs are 4690 updates.

4.3.4 · slides 198–204

Hand-worked mini-batch trace

With \(K = 3\), \(d = 2\), \(B = 2\), \(\eta = 0.1\): compute \(Z_B = X_B W\), apply softmax row by row (the deck gets \((0.280, 0.378, 0.342)\) and \((0.387, 0.315, 0.298)\)), subtract the one-hot labels, form \(\frac{1}{B} X_B^\top(\hat{Y}_B - Y_B)\) and update \(W\). The error matrix has a negative entry exactly at each true class.

4.3.5 · slides 206–211

Inference and multi-class evaluation

At inference compute logits, softmax and take the argmax (the deck's logits \((1.2, 2.5, 0.8)\) give class 2 with 68.7% confidence). Evaluate with the \(K \times K\) confusion matrix and per-class precision/recall; macro-averaging treats every class equally, weighted averaging weights by class frequency, and top-5 accuracy counts a hit if the true class is among the five highest scores.

4.3.6 · slides 214–221

Regression vs binary vs multi-class (the table to memorise)

Regression: identity activation, MSE, output in \((-\infty, \infty)\), one output neuron, \(w \in \mathbb{R}^{d+1}\). Binary: sigmoid, BCE, output in \((0, 1)\), one neuron, \(w \in \mathbb{R}^{d+1}\). Multi-class: softmax, CCE, a probability vector, \(K\) coupled neurons, \(W \in \mathbb{R}^{(d+1) \times K}\).

4.4 · slides 227–230

Numerical stability: subtract the max, log-sum-exp

\(e^{z}\) overflows for \(z \approx 1000\) and \(\log 0\) blows up, so compute softmax as \(e^{z_k - c}/\sum_j e^{z_j - c}\) with \(c = \max_k z_k\) (allowed by translation invariance) and compute losses from logits with the log-sum-exp trick. Standardise features too, so sigmoids do not saturate.

4.5 · slide 224

Debugging a classifier

NaN loss: \(\eta\) too large, \(\log 0\), unscaled features or unstable softmax. Predicting one class: class imbalance, wrong one-hot encoding, a softmax or loss bug, or \(\eta\) too small. Sanity checks: a tiny dataset should reach 100% accuracy, outputs should lie in \((0, 1)\) and sum to 1.

4.5 · slide 225
M5 · Deep Feed-Forward Neural Networks · 19 items

Why one linear layer is not enough

A single neuron, whatever its activation, has a linear decision boundary \(w_1 x_1 + w_2 x_2 + b = 0\), so it fails on XOR and on most real tasks (pixels to objects, words to sentiment). A 2-2-1 MLP solves XOR: each hidden unit draws one line, the hidden layer maps the inputs into a space where the classes are separable, and the output combines them.

5.1 · slides 237–241

Non-linearity, and why stacked linear layers collapse

A function is non-linear if \(f(a x_1 + b x_2) \ne a f(x_1) + b f(x_2)\). Without a non-linear activation, \(XW_1W_2 = X(W_1W_2)\): any number of linear layers equals one linear layer, so depth adds nothing; the activation is what lets depth create new decision boundaries.

5.2.1 · slide 243

Sigmoid, tanh and ReLU compared

Sigmoid: range \((0, 1)\), not zero-centred, maximum derivative 0.25. Tanh: range \((-1, 1)\), zero-centred, maximum derivative 1 (four times sigmoid's), \(\tanh'(z) = 1 - \tanh^2(z)\). ReLU: range \([0, \infty)\), derivative 1 for \(z > 0\) and 0 otherwise. For \(z = (2.0, -1.5, 0.8, -0.3)\) the sigmoid derivatives are only \((0.105, 0.149, 0.214, 0.245)\) while tanh gives \((0.070, 0.181, 0.559, 0.915)\).

5.2.2 · slides 244–245, 344–356

Why ReLU, and the dying-ReLU problem

ReLU is cheap (no exponentials), does not saturate for \(z > 0\) (gradient exactly 1, so it flows unchanged through many layers), and gives sparse activations. A unit whose pre-activation is negative for every input outputs 0 and gets zero gradient forever ("dying ReLU"); Leaky ReLU, PReLU or ELU keep a small slope for \(z < 0\). ReLU is the default for hidden layers; sigmoid belongs only in a binary output.

5.2.3 · slides 245–246, 285

The DFNN is the same four-part recipe with depth

A deep feed-forward network applies, for \(\ell = 1, \dots, L\), \(z^{(\ell)} = h^{(\ell-1)} W^{(\ell)} + b^{(\ell)}\) and \(h^{(\ell)} = \sigma^{(\ell)}(z^{(\ell)})\), starting at \(h^{(0)} = x\) and ending at \(\hat{y} = h^{(L)}\). In the deck's row convention \(W^{(\ell)} \in \mathbb{R}^{n_{\ell-1} \times n_\ell}\), \(L\) counts layers excluding the input, and a mini-batch stacks rows into \(H^{(\ell)} \in \mathbb{R}^{B \times n_\ell}\).

5.3.1 · slides 248–253

Hand-worked forward pass

For the 2-3-2 net with \(x = (1.0, 0.5)\): \(z^{[1]} = (0.7, -0.1, 0.2)\), ReLU gives \(a^{[1]} = (0.7, 0, 0.2)\) (neuron 2 is inactive), \(z^{[2]} = (0.6, -0.02)\) and the sigmoid outputs are \((0.646, 0.495)\). Keep every \(z\) and \(h\): the backward pass reuses them.

5.3.1, 5.4.4 · slides 303–313

Counting parameters

Layer \(\ell\) has \(n_{\ell-1} n_\ell\) weights plus \(n_\ell\) biases, \(n_\ell(n_{\ell-1} + 1)\) in all. For 784-256-128-10 that is 200,960 + 32,896 + 1,290 = 235,146 parameters; the first layer dominates because it touches the high-dimensional input.

5.3.2 · slide 254

Pairing the loss with the output activation

Regression: \(K\) identity outputs with MSE. Binary: one sigmoid output with BCE. Multi-class: \(C\) softmax outputs with CCE. The pairing is not cosmetic; it is what makes the output error signal take the clean form \(\hat{y} - y\).

5.3.3, 5.6.1 · slides 255–256, 283

Output-layer error \(\delta^{(L)} = \hat{y} - y\)

For MSE + identity, BCE + sigmoid and CCE + softmax alike, \(\partial \ell / \partial z^{(L)} = \hat{y} - y\). In the worked example \(\delta^{[2]} = (0.646 - 1, 0.495 - 0) = (-0.354, 0.495)\). Divide by the batch size \(B\) in exactly one place (the slides put \(1/B\) both in \(\delta^{(L)}\) and in the weight gradient, which double-counts it).

5.4.1 · slides 265, 317, 349

The backpropagation recursion

Each hidden error is the next layer's error sent back through the transposed weights and scaled by the local slope: \(\delta^{(\ell)} = (\delta^{(\ell+1)} W^{(\ell+1)\top}) \odot \sigma'(z^{(\ell)})\). In the example \(W^{[2]\top}\delta^{[2]} = (-0.043, 0.382, -0.361)\), and the ReLU mask \((1, 0, 1)\) zeroes the inactive neuron's error, so its incoming weights get no update.

5.4.2 · slides 266–267, 321–324

Parameter gradients and the update

Once \(\delta^{(\ell)}\) is known, \(\partial J / \partial W^{(\ell)} = \frac{1}{B} H^{(\ell-1)\top} \delta^{(\ell)}\) (input activation times error, an outer product for one example) and \(\partial J / \partial b^{(\ell)}\) is the batch mean of \(\delta^{(\ell)}\). With \(\eta = 0.1\) the example's \(b^{[2]}\) moves from \((0.2, -0.1)\) to \((0.235, -0.150)\).

5.4.3 · slides 268–269, 272, 319, 325, 328–330

Full hand-worked backward pass

With target \(y = (1, 0)\) and BCE, the loss is \(-\frac12[\log 0.646 + \log 0.505] = 0.560\). The pass goes: output error, output-layer gradients \(\delta^{[2]} a^{[1]\top}\), backpropagate through \(W^{[2]\top}\), apply the ReLU derivative, hidden gradients \(\delta^{[1]} x^\top\), then update every parameter with the same \(\eta\).

5.4.4 · slides 314–331

Why backprop is cheap

Perturbing each of \(P\) parameters separately needs about one forward pass per parameter, \(O(P \times C_{\text{forward}})\). Backprop caches the forward activations and reuses each \(\delta\) for all the weights of its layer, so one forward plus one backward pass (about \(2\,C_{\text{forward}}\)) yields every gradient, a speed-up of about \(P/2\) (about 100,000 times for \(P = 200{,}000\)). It is dynamic programming on the chain rule.

5.4.5 · slide 271

Universal approximation and its caveat

One hidden layer with enough units and a suitable non-linearity can approximate any continuous function on a compact set (Cybenko, Hornik 1989). The theorem guarantees existence, not learnability or efficiency: the required width can grow exponentially, so in practice depth is used instead.

5.5.1 · slide 279

Depth vs width

Depth builds a hierarchy (edges, then textures and shapes, then parts, then objects) and can represent exponentially more functions than a shallow net with the same parameter count. Width adds parallel features and raw capacity but overfits more easily; start with 2–3 hidden layers and grow only if the data supports it.

5.5.2 · slides 277–278, 284

Vanishing and exploding gradients, degradation

Backprop multiplies one factor per layer, so gradients shrink exponentially when the factors are below 1 (early layers stop learning) and blow up when above 1 (NaN or Inf). Separately, very deep plain networks can show higher training error than shallower ones: the degradation problem, an optimisation failure rather than overfitting. ReLU, careful initialisation, normalisation, gradient clipping and residual connections are the answers.

5.5.3 · slide 280

Gradient attenuation through sigmoid layers

With weight norm 0.8 and the maximal sigmoid slope 0.25, each layer multiplies the gradient by 0.2: from 1.0 at the output to 0.2, 0.04 and 0.008, so after three backward steps only 0.8% of the signal reaches the first layer. Even in the best case for the sigmoid, a deep sigmoid stack starves its early layers.

5.7 · slides 333–334

Sizing a network from (d, N, c)

The deck's own rule of thumb (not a standard result) bounds depth by \(L \le \log_2(M/(d \times c)) + 1\) and parameters by \(M/5\). For \(d = 20\), \(M = 800\), \(c = 3\): \(L \le 4.7\), and the parameter cap of 160 rejects [20, 40, 3] (963 parameters) and accepts [20, 6, 3] (147); small data means a small network plus regularisation.

5.6.2 · slides 336–341

Design heuristics and the debugging checklist

Standardise inputs, match output and loss to the task, initialise randomly (Xavier for sigmoid/tanh, He for ReLU, zero biases) and overfit a tiny batch first as a sanity check. NaN loss means numerical instability or \(\eta\) too large; flat loss means \(\eta\) too small or a bug; oscillation means \(\eta\) too large; training loss falling while validation loss rises is overfitting, both high is underfitting.

Why a dense network fails on images

An image is a grid of pixel intensities \(I(x, y)\) (three grids for colour). A 50×50 image already has 2500 inputs and a 1920×1080 photo about 2 million, so a fully connected first layer needs millions of weights per hidden unit set, overfits, and ignores the fact that nearby pixels belong together.

6.1, 6.1.3 · slides 390–397

Locality and sparse connectivity

The patterns that matter (an edge, an eye, a beak) are much smaller than the image, so a neuron does not need to see the whole image to detect one. Each convolutional unit therefore connects only to a small local patch, its receptive field.

6.1.1 · slides 401–402, 409

Parameter sharing and translation equivariance vs invariance

The same pattern can appear anywhere, so one filter is slid over the whole image and its weights are shared across positions. This makes convolution translation-equivariant (shift the input and the feature map shifts the same way); pooling and global averaging then add approximate invariance (the class label does not change when the object moves).

6.1.2 · slides 395–396, 403, 409

Parameter efficiency vs a fully connected layer

Convolution parameters depend only on kernel size and channel counts, never on the image size. For a 28×28×64 input mapped to 128 outputs, a 5×5 conv layer has 204,928 parameters while a dense layer on the flattened 50,176 inputs has 6,422,656, about 31 times more.

6.1.3 · slides 544–545

Hierarchical feature learning

Early layers detect edges, corners and colours with small receptive fields; middle layers combine them into textures and parts; deep layers respond to objects and faces; fully connected layers and softmax make the decision. The typical pipeline is INPUT, then [CONV, ReLU, POOL] repeated, then FC and OUTPUT.

6.1, 6.10 · slides 399, 411–416

Convolution is cross-correlation with learned filters

Deep-learning "convolution" is cross-correlation, \((I \star K)(i, j) = \sum_m \sum_n I(i+m, j+n)K(m, n)\), with no kernel flip. The kernel entries are learnable weights initialised randomly and trained by gradient descent; first-layer filters typically end up as oriented edge detectors without anyone designing them.

6.2.1 · slides 418, 434–436

Sliding the filter by hand

Place the filter at the top-left, multiply elementwise and sum, then slide by the stride, staying fully inside the input (never partially overlapping); repeat row by row. A 3×3 filter on a 6×6 image with stride 1 gives a 4×4 map; with stride 2 a 2×2 kernel on a 4×4 input visits only 4 positions.

6.2.2 · slides 419–427, 569–570

Feature maps and multiple filters

Each filter (plus its bias) produces one feature map whose large values mark where its pattern occurs; a vertical-edge filter and a horizontal-edge filter give two different maps of the same image. \(C_{\text{out}}\) filters give \(C_{\text{out}}\) maps stacked into a volume: 64 filters of size 3×3 on a 32×32×3 input give 30×30×64.

6.2.3 · slides 427–430

Padding: valid, same, full

Without padding the output shrinks by \(k - 1\) per layer and border pixels are used less often. Valid means no padding, same pads \(p = (k-1)/2\) for odd \(k\) and stride 1 so the size is preserved, and full pads \(k - 1\) so every partial overlap is computed.

6.3.1 · slides 438–439

Stride and the output-size formula

\(O = \lfloor (n + 2p - k)/s \rfloor + 1\) is the course's most-used formula: a 224×224 input with \(k = 7\), \(p = 3\), \(s = 2\) gives 112×112, and \(k = 5\), \(p = 2\), \(s = 2\) turns 32 into 16. Stride above 1 downsamples (a learnable replacement for pooling); always floor, and chain the formula layer by layer because off-by-one errors compound.

6.3.2 · slides 440–443, 536–539

Dilated (atrous) convolution

Dilation rate \(r\) spaces the kernel taps \(r - 1\) pixels apart, giving an effective size \(k_{\text{eff}} = k + (k-1)(r-1)\): a 3×3 kernel covers 5×5 at \(r = 2\), 7×7 at \(r = 3\), 9×9 at \(r = 4\), always with 9 weights. Unlike stride it keeps the resolution, which is why segmentation (DeepLab) and audio (WaveNet) use it.

6.3.3 · slides 444–447, 571–576

Receptive-field growth

\(RF_\ell = RF_{\ell-1} + (k_\ell - 1)\prod_{i<\ell} s_i\): stride-1 3×3 layers give 3, 5, 7, 9, so three 3×3 layers see what one 7×7 sees, with fewer parameters and more non-linearities. Strides multiply later growth (conv, pool, conv, pool gives 3, 4, 8, 10), and dilations 1, 2, 4 give 3, 7, 15.

6.3.4 · slides 431–433, 540–543, 577–578

Multi-channel convolution

A filter always spans the full input depth, \(k \times k \times C_{\text{in}}\); it correlates each channel with its own slice, sums across channels and adds one bias, producing a single output channel. On an RGB input a 3×3 filter is 3×3×3, and in the deck's 2-channel example the channel sums \(-4\) and 2 plus bias 2 give output 0.

6.4.1 · slides 448–452, 550–551

Counting convolution parameters

A conv layer has \((k \times k \times C_{\text{in}} + 1) \times C_{\text{out}}\) parameters, independent of height and width, quadratic in \(k\) and linear in the number of filters. A 5×5 layer with 64 filters on RGB has 4,864; a 3×3 layer from 128 to 256 channels has 295,168; and in a small CNN the first dense layer after flattening usually dominates (524,416 of 545,098 in the deck's example).

6.4.2 · slides 435, 451, 475–476, 546–547, 552–553

Channel evolution: spatial size down, channels up

Deep CNNs halve the resolution and double the channels at each stage (224×224×3, 112×112×64, 56×56×128, …). Fine detail needs resolution early; semantic features need many channels later. The slide's "H × W × C stays constant" is loose: the activation volume halves per stage, and it is the per-layer compute that stays roughly constant.

6.4.3 · slides 453–454, 480

Max vs average pooling

Pooling summarises each window by its maximum (keeps the strongest response, the common choice) or its mean (smoother, used near the end). It reduces height and width but not depth, adds tolerance to small shifts, and has zero learnable parameters: only the window size and stride are chosen.

6.5.1 · slides 455–457, 477–478, 554–556

Pooling output size

The convolution formula applies with \(k\) the pool size, usually without padding: a 2×2, stride-2 pool turns 56×56×128 into 28×28×128 and 32 into \(\lfloor 30/2 \rfloor + 1 = 16\). With stride 1 the windows overlap and a 4×4 map becomes 3×3.

6.5.2 · slides 456, 478, 539, 556

1×1 convolution: a per-pixel dense layer across channels

A 1×1×\(C_{\text{in}}\) filter looks at no neighbours; at each pixel it computes a learned weighted sum of the channel values plus a bias, which is a fully connected layer applied independently at every position ("network in network"). It changes the number of channels, keeps the spatial size, and adds non-linearity when followed by ReLU.

6.6.1 · slides 458–460, 557–558

Bottlenecks: reduce, process, expand

Squeezing channels with a 1×1 before an expensive spatial conv and expanding afterwards cuts cost sharply. Correcting slide 461, \(256 \cdot 64 + 25 \cdot 64^2 + 64 \cdot 256 = 135{,}168\) against 1,638,400 for a direct 5×5 is about a 12× saving; the separate 3×3 example is 70,016 vs 590,080 (8.4×), and against a two-conv basic block 16.8×.

6.6.2, 6.10 · slides 461, 483, 559–562

ReLU, flatten, dense and softmax in a CNN

ReLU follows every conv layer (cheap, non-saturating for positive inputs, sparse). The classifier head flattens \(H \times W \times C\) to a vector, applies dense layers \(y = f(Wx + b)\) with \(m(n + 1)\) parameters, and ends in softmax; dense heads are parameter-heavy, lose spatial structure and fix the input size, which is why global average pooling replaced them.

6.7 · slides 462–472

Backprop through a convolution

Because a kernel weight is reused at every output position, its gradient sums over all of them: \(\partial L / \partial K(m, n) = \sum_{i,j} \frac{\partial L}{\partial O(i, j)} I(i + m, j + n)\), itself a correlation of the input with the upstream gradient. The bias gradient is the sum of the upstream gradient, and the input gradient is a full convolution with the flipped kernel.

6.8.1 · slides 437, 563–564

Backprop through max pooling

Max pooling passes each window's upstream gradient only to the position that won the max and gives every other position zero, so you must remember the argmax from the forward pass. Average pooling instead spreads the gradient equally, \(1/k^2\) to each cell of the window.

6.8.2 · slides 565–566

Counting parameters, memory and FLOPs

Activation memory dominates training: a batch of 32 RGB 224×224 images is 18.4 MB, the 112×112×64 output of one 7×7 conv is 98 MB, yet that layer's 9,472 parameters take only 0.036 MB, and training needs extra memory for gradients. Multiply-adds of a conv layer are \(H_{\text{out}} W_{\text{out}} k^2 C_{\text{in}} C_{\text{out}}\), so the same parameters cost far more at high resolution.

6.9 · slides 544–549, 561–562

Five design patterns of modern CNNs

Spatial reduction plus channel expansion; repeated building blocks (VGG and ResNet blocks); skip connections \(y = F(x) + x\) for gradient flow; 1×1 bottlenecks to cut cost; and multi-scale parallel branches (Inception). Each balances capacity against compute, memory and trainability.

6.10 · slides 479–484

Depth vs width and choosing depth

There is no formula for depth, only heuristics by bucket: MNIST-scale tasks need 5–10 layers, ImageNet 50–152; small datasets (under 10K) call for shallow nets, over 1M for very deep ones; mobile budgets favour efficient 10–20-layer designs. Deeper gives richer features and larger receptive fields but is harder to train; wider trains easily and runs in parallel but overfits more; start from a proven model, add capacity only when underfitting.

6.11 · slides 485–489

LeNet-5

LeCun's 1998 network for handwritten digits on 32×32 grayscale input: CONV, POOL, CONV, POOL, FC, FC, OUTPUT, with tanh/sigmoid activations, average-pool subsampling and about 60K parameters. Its 32×32×3 analogue goes 28×28×6, 14×14×6, 10×10×16, 5×5×16, the template every later CNN refines.

6.12.1 · slides 491–492

AlexNet

The 2012 ImageNet winner (top-5 error 15.3%) that started the deep-learning boom: 5 conv and 3 FC layers, about 60M parameters, 224×224×3 input. Its innovations were ReLU instead of sigmoid/tanh, dropout, data augmentation, GPU training and local response normalisation.

6.12.2 · slides 493–494

VGGNet

VGG-16/19 (2014) uses only 3×3 convs (stride 1, pad 1) and 2×2 max pools, 13 conv + 3 FC layers and about 138M parameters. Two stacked 3×3 convs see 5×5 with \(18C^2\) instead of \(25C^2\) weights and an extra non-linearity; most of the parameters sit in the dense layers.

6.12.3 · slides 495–496

Network in Network and global average pooling

NiN (2013) replaces each linear filter with a small MLP (MLPconv, implemented as a conv followed by 1×1 convs with ReLU) and replaces the dense head with global average pooling, which averages each final feature map to one number. GAP has no parameters, accepts any input size, reduces overfitting, and became standard; NiN also introduced the 1×1 convolution.

6.12.4 · slides 497–501

GoogLeNet and the Inception module

Inception runs 1×1, 3×3, 5×5 convs and a 3×3 pool in parallel and concatenates them (64 + 128 + 32 + 32 = 256 channels), letting the network choose the scale. Placing 1×1 reductions before the 3×3 and 5×5 branches cuts about 390M multiply-adds to about 118M (3.3×), so GoogLeNet reaches 22 layers with only 5M parameters (6.67% top-5 error); this 3.3× is a different worked example from the generic bottleneck savings.

6.12.5 · slides 502–508

ResNet: residual learning and the degradation problem

A 56-layer plain network had higher training error than an 18-layer one: degradation, an optimisation failure, not overfitting. ResNet learns the residual \(F(x) = H(x) - x\) and outputs \(H(x) = F(x) + x\), so representing the identity just means pushing \(F\) to 0; this made 152-layer nets trainable (3.6% ImageNet error, 2015).

6.12.6 · slides 509–510, 516

Basic vs bottleneck residual blocks; projection shortcuts

The basic block (ResNet-18/34) is two 3×3 convs with BN and ReLU plus the identity; the bottleneck block (ResNet-50/101/152) is 1×1 reduce, 3×3 process, 1×1 expand, 70K vs 590K parameters at 256 channels. When shapes change, a 1×1 conv with stride 2 on the shortcut (a projection) matches the dimensions.

6.12.6 · slides 511–514

Why residual connections work: the gradient highway

Since \(\partial L/\partial x = \frac{\partial L}{\partial y}(1 + \partial F/\partial x)\), the "1" gives the gradient a direct path that no chain of small Jacobians can shrink to zero. A network of \(n\) blocks also behaves like an ensemble of \(2^n\) paths of different depths, and later layers can reuse earlier features.

6.12.6 · slide 515

Transfer learning strategies

Start from a model pre-trained on a large source task (ImageNet, 1.2M images, 1000 classes), because low-level features such as edges transfer. Feature extraction freezes the backbone and trains only a new classifier; fine-tuning trains everything with a small learning rate; selective fine-tuning freezes early layers and tunes later ones.

6.13.1 · slides 518–521

Choosing a transfer strategy from size and similarity

Small and similar: feature extraction. Medium-to-large and similar: fine-tune all layers with a low learning rate. Medium, different but related: selective fine-tuning of the later layers. Large and very different: train from scratch. Dataset size decides how many parameters you can safely train; similarity decides which pre-trained layers (the generic early ones) are worth keeping.

6.13.2 · slide 522

CNN application families

Classification assigns one label per image (CNN, GAP or FC, softmax, cross-entropy). Detection outputs boxes plus labels, with two-stage R-CNN/Fast/Faster R-CNN or one-stage YOLO/SSD. Semantic segmentation labels every pixel with FCN, U-Net (encoder–decoder with skips) or DeepLab (atrous convolutions); CNNs also do 1-D time series, audio and text.

6.14 · slides 524–527

Practical CNN training and debugging

Normalise pixels, augment (flips, crops, rotations, colour jitter), use batch norm, dropout, LR schedules, early stopping and pre-trained models. High training but low validation accuracy is overfitting (more data or augmentation, dropout, L2); poor on both is underfitting (bigger model, train longer, less regularisation); vanishing gradients call for proper init, BN and residuals.

Why feedforward networks fail on sequences

Text, speech, video, prices and DNA are ordered and their elements depend on one another. A feedforward net needs a fixed input size, has no memory and uses different weights per position, so it cannot carry "France" seven words forward to predict "fluent French"; sequence models must remember relevant context and forget the rest, over both short and long ranges.

7.1 · slides 583–585

Autoregressive decomposition

By the chain rule, \(P(x_1, \dots, x_T) = \prod_t P(x_t \mid x_1, \dots, x_{t-1})\): each element is predicted from everything before it, so "The cat sat on the mat" becomes \(P(\text{The})P(\text{cat} \mid \text{The}) \cdots\). It is exact, but the conditioning history grows with \(t\).

7.2.1 · slides 587–588

The k-th order Markov assumption

Truncating the history to the last \(k\) steps, \(P(x_t \mid x_{t-k}, \dots, x_{t-1})\), gives a fixed-size, tractable context (bigram for \(k = 1\), trigram for \(k = 2\)). The price is that anything older than \(k\) steps, "cat" and "sat" when predicting "mat" with a bigram, is invisible.

7.2.2 · slides 589–590

Latent-variable (hidden-state) models

Instead of a window, summarise the whole past in a fixed-size hidden state updated recursively, \(h_t = f(x_t, h_{t-1})\), and predict from it, \(P(x_t \mid h_t)\). The state can encode a trend (warming, peak, cooling in the temperature example) without storing every value; this is exactly what an RNN implements.

7.2.3 · slides 591–592, 595

Autoregressive forecasting and error accumulation

With the first-order model \(T_{t+1} = 0.8\,T_t + 4\), today's 21°C gives 20.8°C tomorrow and, feeding that prediction back in, 20.64°C the day after. Recursive multi-step forecasts reuse their own outputs, so errors accumulate, and a first-order model cannot see weekly or seasonal patterns.

7.10, 7.2.2 · slides 593–594

The vanilla RNN and parameter sharing

\(h_t = \phi(W_{hh} h_{t-1} + W_{hx} x_t + b_h)\) with \(h_0 = 0\) and usually \(\phi = \tanh\) (zero-centred). The same \(W_{hx}\), \(W_{hh}\), \(W_{ho}\) and biases are reused at every time step, so the parameter count does not depend on the sequence length, any length can be processed, and a pattern learned at one position transfers to others.

7.3.1 · slides 597–599, 601, 607

Outputs and the RNN parameter count

Each step emits logits \(o_t = W_{ho} h_t + b_o\) and a softmax over the vocabulary. The count is \(hd + h^2 + h + Vh + V = h(d + h + V + 1) + V\); with \(d = 100\), \(h = 256\), \(V = 10{,}000\) that is 2,661,392, of which the output layer takes about 96%.

7.3.2 · slides 600, 602–603

Hand-worked forward pass over two steps

With \(h_0 = 0\), \(x_1 = (1.0, 0.5)\): \(z_1 = (0.75, 0.50, 0.30)\), \(h_1 = \tanh(z_1) = (0.635, 0.462, 0.291)\); then \(h_1\) feeds step 2 with \(x_2 = (0.8, 1.2)\), giving \(z_2 = (1.172, 1.047, 0.680)\) and \(h_2 = (0.826, 0.780, 0.592)\). The recurrent term is zero only at \(t = 1\).

7.3.3 · slides 604–606

Unrolling and the sequence loss

Training maximises the sequence likelihood, i.e. minimises the summed per-step cross-entropy \(L = \sum_t \ell_t\) (the average per-token loss is what gets reported). Unrolling the loop over \(T\) steps turns the RNN into a deep feedforward graph with tied weights, on which ordinary backpropagation runs from \(t = T\) back to \(t = 1\).

7.4.1 · slides 609–612

BPTT: the hidden-state gradient recursion

\(h_t\) affects the loss directly through \(\ell_t\) and indirectly through every later state, so \(\partial L/\partial h_t = \partial \ell_t/\partial h_t + (\partial L/\partial h_{t+1})(\partial h_{t+1}/\partial h_t)\), with \(\partial h_{t+1}/\partial h_t = \operatorname{diag}(1 - h_{t+1}^2) W_{hh}\) for tanh. The recursion starts at the last step, where only the local term exists.

7.4.2 · slides 613, 616

BPTT: parameter gradients are sums over time

Because the same weights act at every step, each parameter gradient is the sum of the per-step contributions, e.g. \(\partial L/\partial W_{ho} = \sum_t (\partial \ell_t/\partial o_t) h_t^\top\) and \(\partial L/\partial W_{hh} = \sum_t (\partial L/\partial h_t)\operatorname{diag}(1 - h_t^2) h_{t-1}^\top\). Then one gradient-descent step updates the shared weights.

7.4.3 · slide 617

Hand-worked three-step BPTT

Inputs \((1,0), (0,1), (1,1)\) give \(h_1 = (0.380, 0.197)\), \(h_2 = (0.499, 0.520)\), \(h_3 = (0.803, 0.754)\). With target \((1, 0)\) at step 3 the output error is \(\operatorname{softmax}(o_3) - y_3 = (-0.496, 0.496)\) and \(\partial L/\partial h_3 = W_{ho}^\top(-0.496, 0.496) = (-0.149, 0.149)\), which is then passed back to \(h_2\) through \(\operatorname{diag}(1 - h_3^2)W_{hh}\).

7.4.4 · slides 614–616

Vanishing and exploding gradients through time

\(\partial L/\partial h_1\) contains the product of \(T - 1\) Jacobians \(\operatorname{diag}(\phi'(z_t))W_{hh}\). If \(\lVert W_{hh} \rVert < 1\) and \(\lvert \phi' \rvert < 1\) it shrinks exponentially, so early steps get almost no signal and long-range dependencies cannot be learned; if \(\lVert W_{hh} \rVert > 1\) it can explode. Fixes: LSTM/GRU, careful initialisation, skip connections and gradient clipping.

7.5.1 · slides 618, 620

The numerical decay example

With \(\lambda_{\max}(W_{hh}) = 0.8\) and \(\lvert \phi' \rvert \approx 0.5\), each step multiplies the gradient by 0.4: \(0.4^5 = 0.01024\) (about 1%), \(0.4^{10} \approx 10^{-4}\), \(0.4^{20} \approx 10^{-8}\). A dependency 20 steps back is effectively unlearnable, which is why "France … fluent …" fails for a vanilla RNN.

7.5.2 · slide 619

Bidirectional RNNs

Run one RNN left-to-right and another right-to-left and concatenate \(h_t = [\overrightarrow{h}_t; \overleftarrow{h}_t]\), so every position sees both past and future (needed for "I met Paris in Paris", sentiment, NER, translation encoders). It needs the whole sequence first and doubles the recurrent cost, so it is wrong for language modelling, streaming speech or forecasting; with \(h_f = h_b = 128\) the deck's example has 2,628,624 parameters.

7.6 · slides 622–628

Deep (stacked) RNNs

Layer \(\ell\) takes layer \(\ell - 1\)'s hidden state as its input, \(h_t^{(\ell)} = \phi(W_{hh}^{(\ell)} h_{t-1}^{(\ell)} + W_{hx}^{(\ell)} h_t^{(\ell-1)} + b^{(\ell)})\), building hierarchies such as characters, words, phrases. Gradients must flow both horizontally (time) and vertically (depth), compounding the vanishing problem, so 2–4 layers is the practical limit, with LSTM/GRU cells, residuals and layer norm.

7.7 · slides 630–637

GRU gates: reset, update and candidate

Gates are sigmoid layers in \((0, 1)\) that scale information elementwise. The reset gate \(r_t\) decides how much of \(h_{t-1}\) enters the candidate \(\tilde{h}_t = \tanh(W_h x_t + U_h(r_t \odot h_{t-1}) + b_h)\) (\(r_t \approx 0\) computes it from \(x_t\) alone, useful at a topic change); the update gate \(z_t\) decides how much of the old state to keep.

7.8.1 · slides 639–644

GRU update as interpolation (and the slide 643 slip)

\(h_t = z_t \odot h_{t-1} + (1 - z_t) \odot \tilde{h}_t\), so \(\partial h_t/\partial h_{t-1}\) contains the term \(z_t\) with no weight matrix and no activation derivative, an additive path like a residual connection. With this equation \(z_t \approx 1\) keeps the old state and \(z_t \approx 0\) takes the candidate; slide 643 states the reverse, and libraries differ, so always read the update equation.

7.8.2 · slides 643, 645, 652

Hand-worked GRU step

From \(x_t = (1.0, 0.5)\) and \(h_{t-1} = (0.6, 0.4)\): \(r_t = \sigma(0.74, 0.54) = (0.677, 0.632)\), \(z_t = \sigma(0.81, 0.67) = (0.692, 0.662)\), \(r_t \odot h_{t-1} = (0.406, 0.253)\), \(\tilde{h}_t = (0.696, 0.475)\), and \(h_t = (0.629, 0.426)\), about 69% old state and 31% new.

7.8.3 · slides 647–650

LSTM gates and the two states

The LSTM separates a cell state \(c_t\) (long-term memory, the information highway) from the hidden state \(h_t\) (working memory and output). The forget gate \(f_t\) erases parts of \(c_{t-1}\), the input gate \(i_t\) admits the candidate \(\tilde{c}_t\), and the output gate \(o_t\) chooses what to expose, \(h_t = o_t \odot \tanh(c_t)\), so the cell can remember without outputting.

7.9.1 · slides 654–658, 660

The additive cell update beats vanishing gradients

\(c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t\) is additive, so \(\partial c_t/\partial c_{t-1} = f_t\) (plus indirect terms): no weight matrix, no squashing derivative. When the network keeps \(f_t \approx 1\), information and gradient survive hundreds of steps, a direct fix for the product of Jacobians in the vanilla RNN.

7.9.2 · slides 659, 663

Gated-cell parameter counts; GRU vs LSTM

Each gate or candidate has its own \(W\) (\(h \times d\)), \(U\) (\(h \times h\)) and bias, so a GRU cell has \(3(hd + h^2 + h)\) and an LSTM cell \(4(hd + h^2 + h)\) parameters: 274,176 vs 365,568 for \(d = 100\), \(h = 256\). The GRU is about 25% smaller and faster and suits smaller data and shorter sequences (50–100 steps); the LSTM is preferred for very long sequences and more data.

7.9.3 · slides 651, 662, 664, 672

Time-series forecasting with RNNs

Univariate input is one variable per step (daily temperature); multivariate input is a vector per step (temperature, humidity, pressure) and captures cross-variable effects. Single-step (many-to-one) predicts \(\hat{x}_{t+1}\); multi-step (many-to-many) predicts several future values directly; the deck's example feeds 7 days of 3 features to an LSTM (\(h = 64\)), predicts tomorrow's temperature, trains with MSE and reports RMSE/MAE.

7.10 · slides 666–670
M8 · Attention Mechanism · 17 items

Why encoder–decoder: T ≠ T′

In translation, summarisation or question answering the output length \(T'\) differs from the input length \(T\) (a 10-word question, the one-word answer "1947"), so an RNN emitting one output per input cannot work. The encoder reads the whole input into a context \(c = h_T^{\text{enc}}\); the decoder starts from \(c\) and generates tokens autoregressively, \(P(y_t \mid y_{<t}, c)\), until an end token.

8.1.1 · slides 678–682

Teacher forcing vs free running; exposure bias

During training the decoder is fed the ground-truth previous token (teacher forcing), which is fast and stable; at inference it must feed back its own predictions (free running), with greedy or beam search (typical beam 5). The mismatch is exposure bias: the model never practised recovering from its own mistakes, so errors can compound at test time.

8.1.2 · slides 683, 719

The fixed-context bottleneck

Every input token must squeeze through one fixed-size vector (say 512 numbers), which weights all parts equally and forgets early tokens; Sutskever et al. saw performance drop sharply beyond about 30 tokens. In the laptop review the decisive "very disappointed" at the end and the early "good impressions" share the same vector, and this specific failure is what attention fixes.

8.1.3 · slides 684–686

Attention as a dynamic context

Instead of one \(c\), the decoder builds a fresh context \(c_t = \sum_i \alpha_{t,i} h_i\) at every step, with weights learned from data that focus on the relevant input positions. Bahdanau (2014) introduced this for translation, it improved long sentences markedly, and it led to the Transformer (2017), now used across NLP, vision, speech and multimodal models.

8.1.3, 8.2.1 · slides 688–690, 697

Attention is a softmax-weighted average

Scores \(e_i = \text{score}(q, k_i)\) are normalised by softmax into weights \(\alpha_i\) that are positive and sum to 1, and the output is \(\sum_i \alpha_i v_i\). It is soft, query-dependent pooling between max pooling (hard selection) and average pooling (uniform weights): weights \((0.03, \dots, 0.22)\) over seven gold prices give a context of about 6261, dominated by the recent days.

8.2.1 · slides 692–696, 703

Query, key and value roles

Like a database lookup: the query is what I am looking for (the decoder state), the keys are what each item is indexed by (encoder states), and the values are what gets returned (often the same encoder states). The query is matched against every key, and the matching scores decide how much of each value is retrieved.

8.2.2 · slides 699–702

Dot-product scores (and the slide 706 slip)

The simplest score is \(q^\top k\): no parameters, one matrix product \(QK^\top\) for all pairs, but it needs \(d_q = d_k\). For \(q = (0.8, 0.6)\) and keys \((0.5, 0.3), (0.9, 0.7), (0.4, 0.2)\) the scores are 0.58, 1.14, 0.44 and the softmax weights are \((0.276, 0.484, 0.240)\), not the slide's \((0.21, 0.62, 0.17)\); the ranking is right, the numbers are not.

8.3.1 · slides 705–706

Why scale by \(\sqrt{d_k}\)

If query and key components have unit variance, \(q^\top k\) has variance \(d_k\), so for \(d_k = 512\) scores are huge, softmax saturates to nearly one-hot and its gradient vanishes. Dividing by \(\sqrt{d_k}\) restores unit variance and healthy gradients, which is why \(\operatorname{softmax}(QK^\top/\sqrt{d_k})V\) is the Transformer default.

8.3.1 · slides 707–708

Additive (Bahdanau) and multiplicative (Luong) scores

Additive attention scores with a one-hidden-layer network, \(v^\top \tanh(W_q q + W_k k)\): learnable, non-linear, and it handles \(d_q \ne d_k\), but it is slower (about \(O(dh)\) per pair) and parallelises worse. Luong's \(q^\top W k\) adds a learned bilinear map. Additive suited 2014–2016 RNN models; scaled dot-product, 3–5 times faster on GPUs, won in the Transformer era.

8.3.2 · slides 709–712

Bahdanau's five-step decoder pipeline

At each decoder step: align \(e_{t,i} = v^\top \tanh(W_s s_{t-1} + W_h h_i)\), normalise \(\alpha_{t,i} = \operatorname{softmax}_i(e_{t,i})\), form the context \(c_t = \sum_i \alpha_{t,i} h_i\), update the state \(s_t = \text{RNN}([y_{t-1}; c_t], s_{t-1})\), and output \(\operatorname{softmax}(W_o[s_t; c_t])\). The encoder is a bidirectional RNN, and the alignment matrix for "yah kitaab bahut achchhi hai" to "This book is very good" is nearly diagonal.

8.4 · slides 714–719

Self-attention

Queries, keys and values all come from the same sequence, \(Q = XW_Q\), \(K = XW_K\), \(V = XW_V\), so every position builds its new representation from all positions of its own sequence. This captures intra-sequence relations such as "he" attending to "customer", or an hourly price attending to the same hour a week earlier.

8.5.1 · slides 721–724, 733

Cross-attention

Queries come from one sequence and keys/values from another, \(Q = X_A W_Q\), \(K = X_B W_K\), \(V = X_B W_V\), aligning two sequences: the English words being generated attend to the Hindi source, or stock prices attend to economic indicators. Bahdanau attention is exactly cross-attention, and in a Transformer it links decoder to encoder.

8.5.2 · slides 725–726

Masked (causal) attention

For autoregressive generation, position \(i\) may attend only to positions \(j \le i\): add \(-\infty\) to the scores above the diagonal before softmax, so those weights become exactly 0 and the allowed pattern is lower-triangular. This prevents the model from seeing the future during training (no leakage of tomorrow's price or the next word), as in GPT-style models.

8.5.3 · slides 727–728

Multi-head attention

Run \(h\) attention heads in parallel, each with its own projections \(W_i^Q, W_i^K, W_i^V\), then concatenate and mix with \(W^O\): \(\text{Concat}(\text{head}_1, \dots, \text{head}_h)W^O\). Different heads can capture different relations (syntax vs meaning, short-term vs weekly cycles); with \(d_{\text{model}} = 512\) and \(h = 8\), each head works in \(d_k = d_v = 64\), so the total cost matches one full-width head.

8.5.4 · slides 729–731

Self-attention ignores order (equivariance, not invariance)

Attention weights depend only on content, so shuffling the inputs just shuffles the outputs: \(\operatorname{Attention}(PX) = P\,\operatorname{Attention}(X)\). Strictly this is permutation equivariance (slide 736 says invariance); only a pooled output is invariant. Either way "dog bites man" and "man bites dog" contain identical information to plain self-attention, so position must be injected.

8.6.1 · slide 736

Positional encoding

Add a position vector to each embedding, \(\tilde{x}_i = x_i + p_i\): either learned per position (BERT, GPT-2; cannot extrapolate beyond the training length) or fixed sinusoids (original Transformer; any length). In the sinusoidal scheme dimension pair \(i\) has frequency \(1/10000^{2i/d}\), so low-index dimensions oscillate fastest (wavelength \(2\pi\)) and high-index ones slowest (up to \(2\pi \cdot 10000\)), the reverse of slide 738's bullet; \(PE(pos + k)\) is a linear function of \(PE(pos)\), which lets the model attend by relative offset.

8.6.2 · slides 737–739

Self-attention vs CNN vs RNN

Path length between two positions is \(O(1)\) for self-attention, \(O(\log n)\) for stacked (dilated) convolutions and \(O(n)\) for an RNN, so attention avoids vanishing gradients over distance. It is also fully parallel (an RNN must compute \(h_1, h_2, \dots\) in order), but costs \(O(n^2 d)\) time and \(O(n^2)\) memory, against \(O(nd^2)\) for an RNN, and it needs explicit position information.

8.6.3 · slides 734–735
M9 · Transformer · 17 items

What the Transformer fixes in RNNs

RNNs compute sequentially (no parallelism, slow training), lose long-range information through vanishing gradients (LSTM/GRU still struggle past 100–200 tokens), and compress everything into a fixed-size state. The Transformer ("Attention is All You Need", 2017) drops recurrence: every token attends directly to every other, giving full parallelism, \(O(1)\) paths and memory of all tokens, at an \(O(n^2)\) attention cost.

9.1 · slides 748–751

The overall block diagram

The encoder block is embedding plus positional encoding, then [LayerNorm, multi-head self-attention, add] and [LayerNorm, FFN, add]. The decoder block adds a masked self-attention sub-layer and a cross-attention sub-layer that reads the encoder output \(H_{\text{enc}}\). The encoder builds bidirectional context-aware representations (so "bank" differs in "river bank" and "bank account"); the decoder generates one token at a time.

9.2 · slides 753, 756–758

Input embedding and sinusoidal positional encoding

Tokens are looked up in a learned embedding matrix \(E \in \mathbb{R}^{\lvert V \rvert \times d_{\text{model}}}\) (\(d_{\text{model}} = 512\) base, 1024 large), and a positional encoding of the same width is added elementwise (the slide says "concatenate" but the formula is a sum), \(X = \text{Embedding} + PE\). Without it the encoder could not tell word order apart.

9.3.1 · slides 760–762

Multi-head attention and the position-wise FFN

Attention lets tokens "communicate"; the FFN lets each token "think" on its own: the same two-layer network, expand \(D \to 4D\), ReLU (GELU in ViT/BERT), contract \(4D \to D\), applied independently at every position. The FFN supplies the non-linearity and most of the capacity; attention alone is a weighted average of linear projections.

9.3.2 · slides 763–764

Add & Norm: residuals and LayerNorm around each sub-layer

Each sub-layer is wrapped as \(Z = X + \text{Sublayer}(\text{LN}(X))\) in the deck's pre-LN form. The residual gives a gradient highway (from ResNet) so stacks of 12–96 layers train, and LayerNorm normalises each token's features with learnable \(\gamma, \beta\) and identical behaviour at train and test time, independent of batch size and sequence length.

9.3.3 · slides 765–767

Encoder parameter count \(\approx 12\,d^2\)

Per encoder layer, attention has \(4d^2\) (\(W^Q, W^K, W^V, W^O\)) and the FFN \(8d^2\) (with \(d_{ff} = 4d\)), so about \(12d^2\), two thirds in the FFN; the head count and sequence length do not enter. For \(d = 512\) the exact count with biases and LayerNorms is 3,152,384 vs \(12d^2 = 3{,}145{,}728\) (0.21% off), and \(N\) identical layers are stacked (6 in the original, 12 in BERT-base, 24 in BERT-large).

9.3.4 · slides 768–769

Masked self-attention in the decoder

The decoder's first sub-layer adds a mask with \(-\infty\) above the diagonal before the softmax so position \(t\) sees only positions \(\le t\). This makes training match inference: during training the whole target is fed at once with teacher forcing and every position is predicted in parallel, without any position seeing the token it must predict.

9.4.1 · slide 772

Cross-attention to the encoder output

The second decoder sub-layer takes queries from the decoder and keys/values from \(H_{\text{enc}}\), \(\operatorname{softmax}(Q_{\text{dec}}K_{\text{enc}}^\top/\sqrt{d_k})V_{\text{enc}}\). It is not masked, because the whole source sentence is legitimately known before decoding starts; this is how the target attends to relevant source words.

9.4.2 · slides 771, 773, 775

Decoder parameter count \(\approx 16\,d^2\) and the output layer

A decoder layer has two attention blocks (\(8d^2\)) plus the FFN (\(8d^2\)), about \(16d^2\), a third more than an encoder layer. The final decoder states go through a linear map \(W_{\text{out}} \in \mathbb{R}^{d \times \lvert V \rvert}\) and a softmax to give \(P(y_t \mid y_{<t}, x)\); tokens are chosen by greedy, sampling or beam search, and the vocabulary-sized embedding and output matrices are often the largest single blocks.

9.4.3 · slides 774, 776

ViT: patches, [CLS] and learned positions

A 224×224×3 image is cut into \(N = (224/16)^2 = 196\) patches of 16×16×3 = 768 values, each linearly projected to \(d\) (768 for ViT-Base). A learnable [CLS] token is prepended (197 tokens), learnable 1-D position embeddings are added, a standard encoder stack (12 layers, 12 heads) runs, and the final [CLS] vector goes through LayerNorm and a linear head to the classes.

9.5.1 · slides 779–784

ViT vs CNN: inductive bias vs data hunger

A CNN hard-codes locality and translation equivariance, so it learns well from small data (under about 100K images). A ViT assumes almost nothing, has a global receptive field from layer 1, and must learn spatial structure from data, so it needs large-scale pretraining (ImageNet-21K, JFT-300M) but then scales and transfers better; its cost is quadratic in the number of patches.

9.5.2 · slides 778, 785

Encoder-only (BERT-style)

Bidirectional attention lets every token see the whole input, ideal for understanding: classification, NER (tagging "Teddy was US President" as PER, O, LOC, O), extractive QA, embeddings. It is pretrained by masked language modelling, hiding 15% of tokens and predicting them from both sides ("The [MASK] sat on the mat" gives "cat"); BERT-base has about 110M parameters.

9.6.1 · slides 787–789

Decoder-only (GPT-style)

Causal attention and autoregressive pretraining, \(P(x_t \mid x_{<t})\), make it a text generator: chat, completion, code, few-shot in-context learning. Every position gives a training signal, generation is sequential at inference, and it is the architecture of today's large language models (GPT-4, LLaMA, Mistral, Claude).

9.6.2 · slides 790–791

Encoder–decoder (T5/BART-style)

A bidirectional encoder over the source plus a causal decoder with cross-attention: the natural fit when input and output differ in kind or length, as in translation ("this book is good" to "yeh kitab acchi hai"), summarisation and data-to-text. T5 casts every task as text-to-text and BART pretrains as a denoising autoencoder. The rule: classify or extract, encoder-only; generate, decoder-only; transform one sequence into another, encoder–decoder.

9.6.3 · slides 792–795

Pretrain, then fine-tune

Self-supervised pretraining on terabytes of unlabelled text (MLM, next-token prediction, span corruption) learns general language; supervised fine-tuning on 1K–100K labelled examples adapts it with a small learning rate (2e-5 to 5e-5), 2–5 epochs, weight decay and clipping. Training BERT-base from scratch on 2,000 reviews would mean about 55,000 parameters per example, hopeless; fine-tuning reuses what pretraining already learned.

9.7.1 · slides 796–805

LoRA: parameter-efficient fine-tuning

LoRA freezes a pretrained \(W\) and trains a low-rank update \(\Delta W = BA\) with rank \(r \ll d\), so \(W_{\text{new}} = W + \alpha BA\). For a 768×768 projection with \(r = 8\) it trains 12,288 parameters instead of 589,824 (2.1%), and on \(W^Q, W^V\) of all 12 BERT layers only about 0.27% of the model; \(B\) starts at zero so training begins exactly at the pretrained model.

9.7.2 · slide 806

Choosing the evaluation metric by task

Classification uses accuracy, F1 and the confusion matrix; NER uses entity-level F1; extractive QA uses exact match and token-overlap F1; translation uses BLEU (n-gram precision), summarisation ROUGE (n-gram recall), and language modelling perplexity, \(\exp(\text{mean token cross-entropy})\), where lower is better and a PPL of 4 means "as unsure as a uniform choice among 4 tokens".

9.7.3 · slide 805
M10 · Optimizers · 17 items

Why optimisation is hard: non-convexity, saddles, plateaus

Deep nets have millions of parameters and no closed-form minimiser, so they are trained iteratively on a non-convex loss with many local minima, where different initialisations reach different solutions. In high dimensions saddle points (zero gradient, up in some directions and down in others) and plateaus (tiny gradients) are the bigger obstacles; a stalling loss with \(\lVert \nabla L \rVert \to 0\) and high validation error is the symptom.

10.1 · slides 812, 815–816, 855

One gradient-descent step

On \(f(x, y) = x^2 + y^2\) from \((3, 4)\) with \(\eta = 0.1\): the gradient is \((6, 8)\), the step lands at \((2.4, 3.2)\) and the loss drops from 25 to 16, a 36% reduction. Each step multiplies every coordinate by \(1 - 2\eta = 0.8\) here, the template for analysing every optimiser on a quadratic.

10.1 · slide 813

Batch, stochastic and mini-batch gradient descent

Batch GD uses all \(N\) examples per update (exact, smooth, memory-hungry, one update per epoch); SGD uses one (cheap, noisy, \(N\) updates per epoch); mini-batch uses \(B\) (vectorised on GPUs, \(\lceil N/B \rceil\) updates per epoch). With \(N = 10{,}000\) and \(B = 32\) that is 1 vs 10,000 vs about 313 updates per epoch; \(B\) from 32 to 256 is the practical default.

10.2 · slides 818–819

The toy loss and what a fixed learning rate does

On the elongated bowl \(L = w_1^2 + 4w_2^2\) from \((4, 2)\), the \(w_2\) direction is four times steeper. Plain GD with \(\eta = 0.1\) multiplies \(w_1\) by 0.8 and \(w_2\) by 0.2 per step (loss 32, 10.88, 6.58, 4.21): \(w_2\) collapses while \(w_1\) crawls. Stability needs \(\eta < 2/\lambda_{\max} = 0.25\); at \(\eta = 0.25\) \(w_2\) flips sign forever and above it diverges, while a tiny \(\eta\) barely moves.

10.3 · slides 820–822

Why per-parameter learning rates help

A single \(\eta\) must suit the steepest direction, so flat directions get tiny steps and the path zig-zags along a ravine. In the toy run \(\nabla w_2\) falls 16, 3.2, 0.64 while \(\nabla w_1\) falls only 8, 6.4, 5.1; scaling each parameter's step inversely to its gradient history (and giving rare, sparse features larger steps) is the idea behind AdaGrad, RMSprop and Adam.

10.3, 10.5 · slides 823, 830–831

Momentum: the heavy ball

Momentum keeps a velocity, \(v_t = \beta v_{t-1} + \nabla L(\theta_t)\), \(\theta_{t+1} = \theta_t - \eta v_t\), with \(\beta = 0.9\) retaining 90% of the previous velocity. Consistent gradient directions accumulate speed (up to \(1/(1-\beta) = 10\) times the step), oscillating components partly cancel, and the ball can roll through small bumps; it costs one extra vector of memory.

10.4.1 · slides 825–827

Momentum on the toy loss

With \(\eta = 0.05\), \(\beta = 0.9\): \(w_1\) goes 4, 3.6, 2.88, 1.94, 0.91, far faster than plain GD, but \(w_2\) overshoots, 2, 1.2, 0, −1.08, −1.62, because the accumulated velocity carries it past the minimum. Momentum amplifies steps, so it needs a smaller \(\eta\) than vanilla GD.

10.4.2 · slide 828

Nesterov accelerated gradient

Nesterov evaluates the gradient at the look-ahead point the velocity is about to carry you to, \(v_t = \beta v_{t-1} + \nabla L(\theta_t - \beta v_{t-1})\). If that point is already past the minimum, the gradient there points back and brakes the step early, so it reacts faster to curvature changes and overshoots less than classical momentum.

10.4.3 · slide 829

AdaGrad and its stall

AdaGrad accumulates squared gradients, \(s_t = s_{t-1} + g_t^2\), and steps by \(\eta g_t/(\sqrt{s_t} + \epsilon)\), so parameters with large past gradients get small effective rates and rare features get large ones (good for sparse NLP features). Because \(s_t\) only grows, the effective rate \(\eta/\sqrt{s_t}\) decays monotonically to zero and learning eventually stops.

10.5.1 · slides 832–833

RMSprop fixes the stall

RMSprop replaces the sum with an exponential moving average, \(s_t = \gamma s_{t-1} + (1-\gamma)g_t^2\) with \(\gamma = 0.9\), so old gradients are forgotten and the rate never vanishes. On the toy loss the first effective rates are \(0.05/\sqrt{6.4} = 0.020\) for \(w_1\) and \(0.05/\sqrt{25.6} = 0.010\) for \(w_2\): the steeper parameter automatically gets the smaller rate. It suits RNNs and non-stationary problems but has no momentum.

10.5.2 · slides 834–838

Adam: momentum plus RMSprop plus bias correction

Adam keeps a first moment \(m_t\) (momentum, \(\beta_1 = 0.9\)) and a second moment \(v_t\) (RMSprop, \(\beta_2 = 0.999\)), corrects their zero-initialisation bias with \(\hat{m} = m/(1 - \beta_1^t)\) and \(\hat{v} = v/(1 - \beta_2^t)\), and steps by \(\eta \hat{m}/(\sqrt{\hat{v}} + \epsilon)\). At \(t = 1\) the corrected ratio is \(\pm 1\), so every parameter moves by exactly \(\eta\) (4 to 3.95 and 2 to 1.95 with \(\eta = 0.05\)); it is the robust default, though tuned SGD+momentum often generalises better in vision.

10.5.3 · slides 838–843

AdamW: decoupled weight decay

Adding \(\frac{\lambda}{2}\lVert \theta \rVert^2\) to the loss in Adam puts \(\lambda\theta\) inside the gradient, where it is divided by \(\sqrt{\hat{v}}\), so parameters with large gradient history are barely regularised. AdamW applies the decay directly, \(\theta \leftarrow \theta - \eta(\hat{m}/(\sqrt{\hat{v}} + \epsilon) + \lambda\theta)\), giving every weight the same shrink rate, usually better generalisation, and the standard for Transformers (\(\lambda = 0.01\)).

10.5.4 · slides 844–845

Learning-rate schedules and warmup

Explore with a large rate early and refine with a small one late. Step decay \(\eta_0\gamma^{\lfloor t/s \rfloor}\) gives 0.1 until epoch 30 then 0.01; exponential decay \(\eta_0 e^{-\lambda t}\) gives 0.061 at epoch 10 for \(\lambda = 0.05\); cosine annealing glides from \(\eta_{\max}\) to \(\eta_{\min}\) (half-way at \(T/2\)); linear warmup ramps from 0 over the first 5–10 epochs (0.04 at epoch 2 of 5), essential for large models and batches.

10.6 · slides 847–851

Gradient clipping

Exploding gradients (NaN, wild loss jumps) are tamed by clipping. Norm clipping rescales \(g\) to length \(\tau\) when \(\lVert g \rVert > \tau\) (typically 1–5) and preserves its direction; value clipping caps each component at \(\pm\tau\) and can change the direction. It is standard for RNNs and Transformers.

10.7 · slides 853–854

Batch size and the linear-scaling rule

Small batches give noisy gradients that act as a regulariser and often generalise better; large batches are GPU-efficient and smooth but take fewer steps per epoch. Since batch size and \(\eta\) interact, double \(\eta\) when doubling the batch (32 at 0.01 becomes 256 at 0.08), with warmup to keep the early large-rate steps stable.

10.7, 10.8 · slides 856, 865

Stopping criteria and early stopping

Combine a maximum epoch count with early stopping: track the best validation loss, stop after \(p\) epochs (the patience, typically 5–10) without improvement, and restore the best checkpoint. In the deck's plot the best model is at epoch 35, training stops at epoch 60 after a patience of 25, and the epoch-35 weights are restored.

10.8 · slides 858–859

Choosing and tuning an optimiser

Start with Adam/AdamW (\(\eta = 0.001\)) and default betas; use SGD+momentum with careful tuning for production vision, RMSprop for RNNs, AdaGrad for sparse data. Tune the learning rate first (log grid, reduce 10 times if the loss explodes), then batch size, then the schedule; common pitfalls are using 0.01 for Adam, scaling the batch without scaling \(\eta\), and not watching loss curves and gradient norms.

10.8 · slides 857, 861–866
M11 · Regularisation of Deep Models · 18 items

Under-, just-right and over-fitting; bias–variance

Too simple a model underfits (high bias, both errors high); too complex a model memorises noise (high variance, training error far below validation error). Expected error is \(\text{bias}^2 + \text{variance} + \text{noise}\), and regularisation trades a little extra bias for a larger drop in variance; networks with millions of parameters can memorise whole datasets, so the more capacity, the more constraint they need.

11.1 · slides 874–877, 893

Explicit vs implicit regularisation

Regularisation is any constraint that stops the model memorising the training data and improves generalisation, often at some cost in training accuracy. Explicit methods change the objective or the architecture (L1/L2 penalties, dropout, DropBlock); implicit ones come from the training procedure (early stopping, normalisation, SGD noise, augmentation). The right mix depends on domain: augmentation and BN for vision, dropout and LayerNorm for NLP, L1/L2 for small tabular data.

11.1 · slides 875–876, 878–879

Vanishing/exploding gradients and internal covariate shift

\(\partial L/\partial W^{(1)}\) contains a product of layer Jacobians, so factors below 1 make it vanish and above 1 make it explode (NaN loss, huge updates). Internal covariate shift is the drift of each layer's input distribution as earlier layers learn, which forces small learning rates and careful initialisation; batch normalisation was introduced to counter it.

11.2 · slides 881–883, 886

Why zero, too-small and too-large initialisation fail

Zero (or any constant) initialisation makes every unit in a layer compute the same function and receive the same gradient, so symmetry never breaks. \(N(0, 0.01^2)\) shrinks activations and gradients layer by layer (vanishing); \(N(0, 1)\) blows them up and saturates sigmoid/tanh (exploding). Since \(\operatorname{Var}(z) = n_{\text{in}}\operatorname{Var}(w)\operatorname{Var}(x)\), the weight variance must scale like \(1/n_{\text{in}}\).

11.3.1 · slides 888–889

Xavier vs He initialisation

Xavier/Glorot keeps activation and gradient variance constant for sigmoid/tanh: \(\operatorname{Var}(w) = 2/(n_{\text{in}} + n_{\text{out}})\) (or \(1/n_{\text{in}}\)). He initialisation uses \(\operatorname{Var}(w) = 2/n_{\text{in}}\) for ReLU, because ReLU zeroes about half the pre-activations and halves the second moment; the factor 2 restores it. For \(n_{\text{in}} = 512\), He gives standard deviation \(\sqrt{2/512} = 0.0625\).

11.3.2 · slides 889–891

L2 (ridge) penalty and weight decay

Adding \(\frac{\lambda}{2}\lVert w \rVert^2\) gives the gradient term \(\lambda w\), so each step multiplies the weights by \(1 - \eta\lambda\) before the loss update: weights shrink smoothly and proportionally but rarely become exactly zero. The slide writes the penalty \(\lambda\sum w_i^2\) with gradient \(\lambda w\); that gradient belongs to \(\frac{\lambda}{2}\lVert w \rVert^2\) (for \(\lambda\sum w_i^2\) it is \(2\lambda w\)). Typical \(\lambda\) is \(10^{-5}\) to \(10^{-2}\).

11.4.1 · slide 894

L1 (lasso) penalty and sparsity

\(\lambda\sum_i \lvert w_i \rvert\) has gradient \(\lambda\operatorname{sign}(w)\), a constant-size push toward zero however small the weight, so many weights land exactly at 0: automatic feature selection. Geometrically the L1 constraint region is a diamond whose corners lie on the axes (L2's is a circle), so the loss contours usually touch it at a sparse corner; it is not differentiable at 0.

11.4.2 · slide 894

Choosing \(\lambda\) with k-fold cross-validation

Split off a test set (for example 80/10/10), then split the training data into \(k\) folds; for each candidate \(\lambda\), train on \(k - 1\) folds, validate on the held-out fold, rotate, and average the \(k\) scores. Pick the best average, retrain, and touch the test set once. It gives more reliable estimates and uses limited data better, at \(k\) times the cost.

11.4.3 · slide 895

Dropout during training

On every forward pass each unit is kept with probability \(1 - p\) and zeroed with probability \(p\) (a fresh Bernoulli mask per unit, per example, per pass), so each pass trains a random thinned sub-network. Units cannot rely on specific partners (no co-adaptation), and the result behaves like an ensemble of exponentially many networks sharing weights; the deck suggests \(p\) around 0.5 for hidden layers and 0.1–0.2 for inputs.

11.5.1 · slides 897–898

Dropout at inference: two equivalent conventions

At test time nothing is dropped. The slide's classic (Srivastava) form scales the weights by \(1 - p\) so each unit's expected input matches training; modern "inverted dropout" (PyTorch, TensorFlow) instead divides kept activations by \(1 - p\) during training and changes nothing at test time. Both keep the expected activation the same; leaving dropout active at test time is a classic bug.

11.5.2 · slide 897

Dropout variants

DropConnect drops individual weights instead of units. DropBlock drops contiguous spatial blocks (around 7×7) of a CNN feature map, because neighbouring pixels are correlated and single-pixel dropout is easily filled in; SpatialDropout drops whole channels. Variational dropout reuses one mask across all time steps of an RNN, and attention dropout (0.1–0.3) drops attention weights in Transformers.

11.5.3 · slides 899, 920–922

Batch normalisation

For each feature, normalise over the mini-batch, \(\hat{x} = (x - \mu_B)/\sqrt{\sigma_B^2 + \epsilon}\), then rescale with learnable \(\gamma, \beta\) so the layer can undo the normalisation if useful; at inference use running averages of the mean and variance. For \(x = (10, 12, 8, 14)\): \(\mu = 11\), \(\sigma^2 = 5\), \(\hat{x} = (-0.45, 0.45, -1.34, 1.34)\), and with \(\gamma = 2\), \(\beta = 3\) the outputs are \((2.1, 3.9, 0.32, 5.68)\); it allows much larger learning rates and adds mild regularising noise.

11.6.1 · slides 900–902

Layer normalisation

LayerNorm normalises across the features of each sample, so it needs no batch statistics, works with batch size 1 and variable sequence lengths, and computes exactly the same thing at train and test time. For one sample \(x = (2, 8, 4, 10)\): \(\mu = 6\), \(\sigma^2 = 10\), \(\hat{x} = (-1.27, 0.63, -0.63, 1.27)\), then per-feature \(\gamma_i, \beta_i\) are applied.

11.6.2 · slides 903–907

BatchNorm vs LayerNorm: when each fits

BatchNorm normalises a feature across the batch and suits CNNs with large, stable batches; LayerNorm normalises a sample across its features and suits RNNs, Transformers and small or variable batches. Both have \(2 \times\) features learnable parameters, but only BatchNorm keeps running statistics and behaves differently at train and test time; batch size 1 breaks it.

11.6.3 · slide 908

Early stopping

Monitor validation loss each epoch; an improvement counts only if it beats the best by at least min-delta (0.001–0.01). Reset the counter and save the weights on improvement, otherwise increment it, stop when it reaches the patience (5–20 epochs), and restore the best weights, not the final ones. It is implicit regularisation: limiting training time limits how far the weights can move toward memorisation.

11.7 · slides 909–910

Data augmentation, Mixup and CutMix

Augmentation enlarges the data with label-preserving transforms: geometric (rotate, flip, scale, crop, translate) and photometric (colour jitter, brightness, contrast, noise) for images, synonym replacement and back-translation for text. Mixup blends two images and their labels, \(\tilde{x} = \lambda x_i + (1-\lambda)x_j\) (0.7 cat + 0.3 dog); CutMix pastes a patch of one image into another and mixes labels by patch area. The deck reports roughly 5–15% generalisation gains.

11.8 · slides 911–914

Architecture-specific regularisation

CNNs: DropBlock, Cutout, SpatialDropout, augmentation, BN after conv and before activation, global average pooling instead of large dense heads. RNNs: input/output dropout, variational or recurrent dropout (same mask across time), gradient clipping, LayerNorm on hidden states. Transformers: attention dropout, layer dropout (skip whole layers), label smoothing (targets \((1 - \varepsilon)y + \varepsilon/K\), so the model is never pushed to infinite confidence), warmup plus decay.

11.9 · slides 920–922

Interactions, common mistakes and debugging

Good pairings are BN + weight decay, augmentation + dropout, L2 + early stopping; risky ones are BN + dropout (put dropout after BN), strong L1 + heavy dropout, heavy augmentation on tiny data. Classic mistakes: dropout left on at test time, BN before the conv instead of conv, BN, activation, keeping the same LR after adding strong regularisation, and augmenting before the train/validation split (leakage). A large train–validation gap means under-regularised; both losses high means over-regularised.

2.1 The spine of the course: six ideas that keep coming back

Students who treat this course as "a new architecture every week" struggle, because every week is secretly the same four-part recipe (1.4) plus one new trick applied to it. The ideas below are what actually need to be mastered; the architectures are mostly consequences of applying them.

# Big idea Where it appears
A Every model is Data → Model → Loss → Learning-algorithm. Linear regression, logistic regression, a DFNN, a CNN, an RNN, a Transformer are all instances of this same four-part recipe; only the "Model" column changes. 1.4, 3.1–3.4, 4.2–4.3, 5.3, 6.1–6.9, 7.3, 9.2–9.4
B Backpropagation is just the chain rule, applied mechanically, right to left. \(\delta^{(L)} = \hat{y} - y\) for every matched loss/activation pair; every subsequent \(\delta\) is "upstream error, routed through a transpose weight matrix, scaled by the local derivative." The exact same recursion reappears as BPTT (unrolled in time) and as backprop-through-convolution/pooling. 5.4, 6.8, 7.4
C Vanishing/exploding gradients is one phenomenon with many fixes. It is a product of many Jacobians each \(< 1\) (or \(> 1\)). It first appears as "why sigmoid/tanh networks are hard to train deep" (5.2, 5.5.3), reappears identically as "why vanilla RNNs forget" (7.5), and is the stated motivation for ReLU (5.2.3), residual connections (6.12.6), LSTM/GRU's additive cell-state update (7.8–7.9), gradient clipping (10.7), and careful initialization (11.3). 5.2–5.5, 6.12.6, 7.5, 7.8–7.9, 10.7, 11.2–11.3
D Softmax/sigmoid + matched cross-entropy has a deceptively simple gradient: (\(\text{prediction} - \text{target}\)). This single fact explains why classification training "just works" with simple code, and it is the reason the course keeps re-deriving \(\delta^{(L)} = \hat{y} - y\) from scratch in every module that has an output layer. 4.2.5, 4.3.3, 5.4.1, 8.4, 9.4.3
E Information bottlenecks motivate the next architecture. A fixed-size hidden state is a bottleneck for an RNN over long sequences (7.5); a fixed-size context vector is a bottleneck for a seq2seq encoder (8.1.3); attention removes that bottleneck by letting the decoder look at all encoder states; the Transformer then removes recurrence itself, trading an information bottleneck for an \(O(n^2)\) compute cost. 7.5, 8.1, 8.6.3, 9.1
F Inductive bias is a dial, not a binary. A CNN hard-codes locality+translation-equivariance (so it needs less data); a Transformer/ViT learns relationships from data with almost no hard-coded structure (so it needs more data, or large-scale pretraining). Every "why does X work" question in this course is really a question about which structural assumption X bakes in. 6.1, 6.12, 9.5.2, 9.6

2.3 The most common misconceptions (targeted by L1 and L5 problems)

Misconception Reality Targeted in
"More layers always helps." Depth without matching data/optimization care causes the degradation problem (deeper plain networks can have higher training error, not just overfitting) — this is literally why ResNet exists. M5, M6
"A model's capacity and its generalization are the same thing." A network can have the capacity to memorize the training set (capacity) yet generalize poorly (high variance); this is the entire reason Module 11 exists as a separate module from "make the model bigger." M5, M11
"Backpropagation is a different algorithm from calculus." It is the multivariable chain rule, applied layer-by-layer, with intermediate values cached from the forward pass so nothing is recomputed. There is no separate "backprop theory." M5, M6, M7
"Dropout is applied at test time too." Dropout masks units only during training; at inference the full (unmasked) network is used (with the classic Srivastava formulation rescaling weights by \((1-p)\), or the "inverted dropout" convention rescaling activations by \(1/(1-p)\) during training so inference needs no change at all). M11
"Softmax outputs are the only way classification can work." Softmax + categorical cross-entropy is the choice that makes the output-layer gradient simplify to \(\hat{y} - y\); a different loss (e.g. a Poisson or margin loss) would not have this convenient gradient and would change the whole backward pass. M4, M5
"Batch Norm and Layer Norm do the same kind of normalization." BatchNorm normalizes a feature across the examples in a batch (needs a reasonably large, consistent batch, and keeps running statistics for test time); LayerNorm normalizes across the features of one example (works for any batch size, including 1, and uses the identical computation at train and test). This is why Transformers/RNNs use LayerNorm and CNNs use BatchNorm. M11
"Stride, padding, and kernel size arithmetic is 'intuitive', no need to memorize the formula." \(O = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1\) is unforgiving: off-by-one errors compound across layers and silently produce the wrong feature-map size, which is a leading cause of real debugging time. M6
"A bigger receptive field always requires a bigger kernel or more pooling." Dilated convolutions grow the receptive field (\(k_{\text{eff}} = k + (k-1)(r-1)\)) with the same parameter count as the un-dilated kernel — no extra parameters, no extra pooling/downsampling. M6
"RNN, LSTM, GRU are three unrelated models you must memorize separately." GRU and LSTM are vanilla-RNN plus an additive, gated path for the hidden/cell state specifically engineered so that \(\frac{\partial h_t}{\partial h_{t-1}}\) (or \(\frac{\partial c_t}{\partial c_{t-1}}\)) contains a term with no weight-matrix multiplication and no activation derivative — i.e., a direct fix for 7.5's vanishing-gradient product. M7
"Attention replaces RNNs because it's 'smarter'." Attention solves a specific, nameable failure mode — the fixed-size context-vector bottleneck of seq2seq RNNs (8.1.3) — not a vague notion of intelligence. Self-attention's \(O(1)\) path length between any two positions is the precise reason it avoids the vanishing-gradient-over-distance problem that plagues RNNs. M7, M8
"The Transformer has no notion of order, so word order doesn't matter to it." Self-attention is provably permutation-invariant (\(\operatorname{Attention}(X) = \operatorname{Attention}(PX)\)); positional encoding is bolted on specifically to inject order information, and removing it (or getting it wrong) breaks any task where order matters. M8, M9
"Adam is strictly better than SGD, so there is no reason to use SGD+momentum." Adam adapts faster and needs less tuning, but SGD+momentum, carefully tuned, often reaches a better final generalization in computer-vision production settings — the slides explicitly present this as a tradeoff, not a strict ordering. M10
"A bigger batch size with the same learning rate trains the same model, just faster." Changing batch size changes gradient noise; the linear-scaling rule (double batch \(\Rightarrow\) double LR, with warmup) exists because batch size and learning rate interact, they are not independent knobs. M10
"L1 and L2 regularization do the same thing, just with a different exponent." L2's gradient is proportional to \(w\) (smooth shrink-toward-zero, never exactly 0); L1's gradient is a constant \(\operatorname{sign}(w)\) (drives many weights to exactly zero, performing implicit feature selection). The shapes of their constraint regions (sphere vs diamond) is why. M11

2.4 Errata and ambiguities spotted in the slides

  1. M2, perceptron output convention: the slides themselves flag this, but it is worth restating because it is a common source of mismatched hand-computations: the perceptron is defined with \(\hat{y} \in \{-1, +1\}\) in the general algorithm (slide "Perceptron Learning Algorithm"), but the worked AND/OR/NOT gate examples immediately switch to \(\hat{y} \in \{0, 1\}\). Both are legitimate formulations of a perceptron, but the bias term you solve for is different between them — state which convention you are using before solving a gate problem.
  2. M5, network-sizing heuristics ("\(L \le \log_2\!\left(\frac{M}{d \times c}\right) + 1\)" and "\(\text{Parameters} \le M/5\)"): these two inequalities are presented without a citation and are not standard results from Goodfellow/Bishop/d2l — they read as a pedagogical rule of thumb specific to this deck, useful for forcing a size-sanity-check discipline, but should not be quoted as a universal law of network sizing in an exam answer without noting that it is the course's own heuristic.
  3. M11, dropout at inference — two non-identical but both "correct" conventions coexist in the same module: the slide's "Inference Phase" formula scales the weights by \((1-p)\) (the original Srivastava et al. 2014 formulation). Modern frameworks (PyTorch/TensorFlow) implement "inverted dropout" instead: they scale the activations by \(1/(1-p)\) during training and apply no rescaling at test time. The two are mathematically equivalent in expectation, but a student who has only used nn.Dropout in PyTorch will not recognize the slide's formula as "the same thing" without this bridge — worth stating explicitly rather than treating it as obvious.
  4. M6, GoogLeNet/Inception-savings arithmetic: the slide's "naive vs. \(1 \times 1\)-reduced" computation (\(\approx 390\text{M}\) vs. \(\approx 118\text{M}\) multiply-adds) is presented as "\(3.3\times\) reduction," which checks out (\(390/118 \approx 3.3\)); however, the deck's separate bottleneck-block slide (Pattern 4) computes an unrelated "\(8\times\) reduction" example (\(590\text{K} \to 70\text{K}\) params) with different filter counts. Both figures are individually correct, but a student skimming could conflate "the Inception savings number" with "the generic bottleneck savings number" — they are two different worked examples, not two statements of the same ratio.
  5. M6, "normal approximation"-style sizing rule reused from statistics courses does not appear here — flagged only to say explicitly that, unlike a statistics course, this deck does not give a single universal rule for "how deep should my CNN be"; Section 6.11's guidance is explicitly a set of heuristics by task/dataset-size bucket (MNIST-scale vs ImageNet-scale vs mobile/edge), not a formula, and should be answered as "it depends on X, Y, Z" rather than a single number in an exam.
  6. M10, the toy optimization problem's claimed iteration numbers are consistent and have been numerically re-verified for this problem bank (e.g., the per-layer vanishing-gradient example \(0.8 \times 0.25\) per layer \(\Rightarrow\) 0.8% of the original gradient after 3 layers, and the RNN decay example \((0.8 \times 0.5)^5 = 1.024\%\), \((0.8 \times 0.5)^{10} \approx 0.01\%\), \((0.8 \times 0.5)^{20} \approx 10^{-8}\) are all exactly reproducible by direct computation) — no error found, noted here only because these are the two numbers most worth re-deriving yourself rather than memorizing, since they are reused as the course's running illustration of vanishing gradients.

2.5 How the problem bank is designed

  • Every leaf of the tree is hit by at least one problem across the module files. Bottleneck nodes — backpropagation (5.4/6.8/7.4), convolution output-size arithmetic (6.3), and the vanishing/exploding-gradient thread (5.5.3/7.5/7.8–7.9) — are hit 4–8 times each, at increasing levels, across different modules.
  • L1 problems check vocabulary and catch misconceptions before any computation starts.
  • L2 problems use small, clean numbers so the mechanics of a formula are separated from reading comprehension — many are built as original variants of the deck's own tiny worked examples (different numbers, same structure).
  • L3 problems are multi-step scenarios at the level the course's own numerical-problem sub-decks (M5's "DFNN Numerical," M6's "CNN Numerical") are pitched at.
  • L4 problems require you to derive: why the softmax+cross-entropy gradient is \(\hat{y} - y\), why He-initialization has a factor of 2 and Xavier does not, why a dilated convolution's parameter count does not grow with the dilation rate, why LSTM's cell-state update is additive and what that buys you algebraically.
  • L5 problems connect a topic to real model-building practice (architecture choice, debugging a stalled training run, choosing BatchNorm vs LayerNorm for a new project) or set a deliberate misconception trap.
  • Each module file ends with a module capstone section that draws on the whole module. The final file in this bank holds cross-module capstones that each deliberately combine three or more modules — e.g. walking through designing, sizing, and debugging a small CNN end-to-end, or deriving the full backprop pass through a tiny network with a nonlinearity and a loss and checking it numerically.

Suggested study loop per topic: do all L1 → all L2 → L3 → L4, checking each answer as you go, then attempt L5 without hints. Re-attempt anything you got wrong 48 hours later — this is especially effective for the four bottleneck skills in §2.2, since they are tested again in every later module.
